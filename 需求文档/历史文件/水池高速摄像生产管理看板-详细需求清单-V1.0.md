## 1. 项目概述

### 1.1 项目背景与目标

在监控室部署一台信息化显示看板，专用显示水池高速摄像检验设备的运行状态与生产管理信息，替代人工纸质台账，实现「设备状态可视、测试过程可追溯、当班产能可量化、异常风险可闭环」。

### 1.2 建设目标（可验收）

- 设备硬件运行状态与核心参数**秒级同步**，状态颜色标识直观可辨；
- 在测工单、测试标准、实测数据、进度**全流程可视化**；
- 当班生产、质检、效率数据**自动统计**，替代人工台账；
- 设备故障、参数超标、生产超时**实时高亮预警**并展示处理进度；
- 设备全生命周期维保、运行、检修数据**留痕可查**；
- 工艺数据按附录 2 规范**周期性上报 MES**，网络异常时可补传、不丢数。

### 1.3 系统边界

**范围内：**

- 看板显示端软件（8 个标签页 + 固定头部区 + 设置页）；
- 数据采集服务（PLC / 相机 / 深度传感器 → 本地库）；
- MES 数据上传通道（HTTP POST，备用 WebService）；
- 本地数据库、配置、日志、开机自启与无人值守运行保障；
- 维保/公告/异常处理状态的本地录入与留痕。

**范围外（需甲方另行提供或确认）：**

- MES 侧的接口开发与工单数据下发功能；
- PLC 程序改造、相机 SDK 与传感器接入的硬件侧实施；
- 车间网络、机柜、电视挂架、电源等弱电施工；
- 生产检验工艺判定规则本身的制定。

### 1.4 用户角色与使用场景

| 角色 | 关注内容 | 交互方式 |
| --- | --- | --- |
| 现场操作员 | 当前工单、实测数据、进度、报警 | 只看不操作（大屏远距离观看） |
| 当班班组长 | 当班产量、合格率、异常闭环、待办 | 只看不操作 |
| 设备维保人员 | 维保周期、检修记录、故障台账 | 解锁后录入维保信息 |
| 车间管理人员 | 公告、工艺提示、效率指标 | 解锁后修改公告 |
| 系统管理员 | 时间、网络、参数、密码 | 设置页 / 远程运维 |

**典型场景：** 看板主机开机后自动全屏启动，默认停留在「设备状态」页，全程无人干预连续显示；维保/公告维护时由授权人员通过外接鼠标或远程桌面解锁设置页操作。

## 3. 系统架构与数据流（建议方案）

### 3.1 分层架构

```
┌────────────────────────── 展示层（看板前端 · 全屏 Kiosk） ──────────────────────────┐
│  固定头部区  │  信息展示区（设备状态 / 任务数据 / 班次信息 / 生产统计 /              │
│              │              设备异常 / 维保台账 / 公告备注 / 操作设置）              │
└───────────────────────────────────┬─────────────────────────────────────────────────┘
                                    │ 本地 WebSocket / HTTP（秒级推送）
┌───────────────────────────────────┴─────────────────────────────────────────────────┐
│  服务层：采集服务（Windows 服务，Java/.NET 均可）                                    │
│  ①PLC/相机取数 ②业务校验 ③落库 ④MES 上报与重传 ⑤异常判定 ⑥班次统计核算            │
└──────────┬────────────────────────────────┬───────────────────────────────────────┘
           │ OPC UA / Modbus TCP / S7        │ HTTP POST（备用 WebService）
┌──────────┴───────────┐        ┌───────────┴────────────┐        ┌──────────────────┐
│ PLC / 相机 / 深度传感器 │        │ MES 系统（工单下发 / 回执）│        │ 本地数据库        │
│ （实时工艺数据源）      │        │                          │        │ SQLite/PostgreSQL │
└───────────────────────┘        └──────────────────────────┘        └──────────────────┘
```

### 3.2 关键数据流

1. **采集流：** PLC 寄存器 / 相机 SDK / 深度传感器 → 采集服务（周期 100 ms～1 s）→ 实时缓存 + 本地库；
2. **工单流：** MES → 采集服务（工单、产品型号、批次、订单号、测试标准、计划数量、人员班次）；
3. **上报流：** 采集服务 → MES（附录 2 定义的 9 个字段，周期上报 + 测试中持续推送）；
4. **展示流：** 采集服务 → 看板前端（1 s 推送，状态/参数/进度实时刷新）；
5. **留痕流：** 解锁后的维保录入、公告编辑、异常闭环操作 → 本地库 + 操作日志。

### 3.3 采集服务建议形态

- 以 **Windows 服务**方式运行（开机自启、崩溃自动重启、无界面）；
- 看板前端建议采用 **Electron 或 Chromium --kiosk** 全屏外壳，便于实现无边框、开机自启、快捷键屏蔽；
- 采集服务与前端之间使用本地回环通信，前端不直连 PLC/MES，便于容错。

## 15. 假设与前提

1. 附录 2 为 MES 上报接口的权威定义，最终字段以 MES 方联调文档为准；
2. 看板所需工单、人员、班次数据由 MES 提供，若 MES 无法提供，则由本地录入补充（需甲方确认）；

4. 75 寸电视作为纯显示设备，日常无需人工交互；
5. 设备编号 `deviceCode` 全场唯一且稳定不变；
6. 班次时间为固定规则配置（非动态排班），如需动态排班需追加需求。
