## 一、结论摘要

**需要修改，且必须修改。** 设计方案第 13.4 节把看板需求原文照搬进来了，但**全文档其余部分没有为这个看板配置任何资源**——没有主机、没有软件条目、没有显示终端、没有数据来源、没有工期与验收项。看板目前是"有需求、无落地"的状态。

| 分类 | 数量 | 说明 |
| --- | --- | --- |
| **A. 设计方案必须修改（缺项，无歧义）** | 11 项 | 供货清单、显示终端、主机位置、软件清单、网络通道、工期、验收、图纸、性能指标、软件设计章节、调试交付物 |
| **B. 设计方案必须修改（内容与技术事实不符）** | 3 项 | 附录 2「数据来源=PLC 寄存器」但全系统无 PLC；附录 2 示例字段名未同步；示例 frameRate=30 与相机 400～1120 fps 不符 |
| **C. 设计方案需要澄清（语义/口径，需甲方决策）** | 3 项 | 「设备编号」粒度、生产口径 vs 试验口径、75″ 电视共用还是增配 |

**最高优先级 3 个阻塞项：**
1. **75″ 电视一物两用冲突**——设计方案 13.3 把 75″ 大屏指派给"两视场多相机实时图像总览"，13.4 又要一台看板，而供货清单只有 1 台电视；
2. **看板主机与看板软件未进供货清单**——BOM 第 17 项软件只有"控制测量软件 MEAS-01"，看板软件与主机缺项，直接影响报价与交期；
3. **附录 2 的"PLC 寄存器"数据来源在全系统中不存在**——全文档无 PLC，看板取数字段无着落，开发无法启动。

## 三、A 类：设计方案必须修改（缺项，无歧义）

### A-1　供货清单缺 3 项关键条目（16.1、5.8）

现状：16.1 供货清单共 17 项，软件只有"控制测量软件 视迈特 MEAS-01 ×1 套"，**无看板软件、无看板主机、无第二块显示终端**。

建议在 16.1 与 5.8 增加：

| 序号 | 名称 | 型号/规格 | 单位 | 数量 |
| --- | --- | --- | --- | --- |
| 18 | 信息化看板软件 | （待定，配套 MEAS-01） | 套 | 1 |
| 19 | 看板主机 | 联想开天 M630Z（兆芯 KX-U6780A/8G/512G，Windows 10/11 x64） | 台 | 1 |
| 20 | 看板显示终端 | TCL 75 寸（4K@30Hz）｜**若与图像总览共用则不加此项** | 台 | 0 或 1 |

> 说明：看板主机型号来自需求 Q-02 答复；**须由甲方确认是否纳入父项目统一采购**（见 Q-30）。

### A-2　75″ 电视用途冲突（13.3 ↔ 13.4 ↔ 16.1）

- 13.3 表 13-4：`75″ 监控大屏 → 两视场多相机实时图像总览、目标轨迹叠加、系统运行态势`
- 13.4：`监控室内布置一台信息化显示看板，专用于显示摄像系统生产管理信息`
- 16.1：液晶电视 TCL 75 寸 **×1**

**同一台电视被指派了两个独占用途。** 必须二选一并在文档中写清：
- **方案甲（增配）**：看板独立用一块 75″，16.1 增加第 20 项，13.3 表 13-4 增加"看板大屏"行，13.1/13.2 增加看板主机位与信号源；
- **方案乙（共用）**：明确切换方式（软件分屏 / KVM / HDMI 切换器）、切换权限与操作位置（控制台能否切换监控室画面），并在 13.3 表 13-4 注明"看板页面与图像总览分时复用"。

### A-3　13.1 监控柜与 13.2 控制台未给看板主机留位

- 13.1 监控柜为 19″ 42U，分 L1 通信 / L2 转换 / L3 存储 / L4 处理 / L5 同步 / L6 供电六层，**无看板主机层位**；
- 13.2 控制台四区（显示区 / 操作面板区 / 键鼠承托区 / 机柜功能舱）**无看板主机位**。
- 建议：在 13.1 增补"L7 看板层：看板主机 ×1（2U 或台式机托架）"，或在 13.2 机柜功能舱内明确预留位置，并同步更新图纸 SC710-UW-10。

### A-4　13 章缺少看板的网络通道与 IP/端口规划

5.7 只有 1 台万兆交换机 TL-SH1832（用于蓄水段图像汇聚）。看板主机**接入哪台交换机、到 MES 的路由、端口开放清单**均未描述。
建议在 13.1 或 13.3 增加：看板主机接入交换机型号与端口号、与 MES 的网段/路由、防火墙放行端口、固定 IP 与 NTP 源（对应需求 DEP-05/06）。

### A-5　附录 2「数据来源」与系统实际不符——**全系统没有 PLC**

附录 2 把 frameRate、gain、shutter、depth、testStatus 的数据来源均写为**"PLC 寄存器"**，但通读全文档：3.1 系统组成、第 5 章选型、9.1 同步链路、13.1 监控柜，**没有任何 PLC 或可编程控制器**。

实际可用来源应为：

| 附录 2 字段 | 现写来源 | 建议改为 |
| --- | --- | --- |
| frameRate 实时帧率 | PLC 寄存器 | 相机 SDK / 采集软件（SHS-201 全幅 1120 fps、SH6-201 1000 fps） |
| gain 相机增益 | PLC 寄存器 | 相机 SDK / 控制测量软件 MEAS-01 参数回读 |
| shutter 快门速度 | PLC 寄存器 | 相机 SDK / MEAS-01 参数回读（**须明确单位：ns / μs / 1-s**） |
| depth 实测水下深度 | PLC 寄存器 | 深度传感器 GLF-DEP-01（×18），经起吊控制上位机或 MEAS-01 读取 |
| testStatus 设备运行状态 | PLC 寄存器 | 控制测量软件状态字 / 同步控制器 LK-CONT-100 状态 |
| collectTime / uploadId | Java 程序 | 保留，但需说明 Java 程序部署在哪台机器（看板主机 or 图像处理单元） |

## 四、B 类：内容与技术事实不符（同上 A-5/A-6/A-7，另补充）

### B-1　13.4 与父项目整体语境不匹配（术语口径）

全文检索结果很说明问题——**"生产、产品、工单、合格、稼动、班次、操作员、班组"这些词只出现在 13.4 节和附录 2 里**，文档其余部分一律是"试验任务、水下航行体、图像数据、测量结果"。这说明：

- 父项目本质是**试验水池的测量系统**（做试验、出测量数据），不是批量生产线；
- 13.4 节要求的是**生产管理看板**（计划数、合格率、产能达成率、设备稼动率、待复检），语义来自批量检验产线；
- 两者的"任务"含义不同：父项目是"试验任务"，看板是"MES 生产任务（procOrderNo）"。

**必须澄清：本看板服务的到底是"产品检验工况"还是"试验工况"？** 若为产品检验，需说明与本改造系统的关系（是同一套设备的另一用途，还是另建工位）；若为试验工况，则 13.4 的产量/合格率/稼动率应改为试验口径（试验次数、有效数据率、单次试验时长等）。

### B-2　13.4 与 13.3 的显示内容边界未划清

13.3 已定义 4 类显示载体（75″ 大屏、操作左屏、操作右屏、面板状态屏），13.4 又定义第 5 类"信息化看板"。建议在 13.3 表 13-4 增加"信息化看板"行，明确其载体、显示内容与刷新方式，避免与既有 4 类混淆。
