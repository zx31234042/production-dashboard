## 背景（为什么必须有这份 ADR）

1. **"有几道门禁"自身有三个口径**（座位 5 实测）：`tests\README.md` 第三节脚本表实为 **21 行**、`tests\run-all.js` 的 `SUITES` 为 **17 条**、README 另一处自述"脚本总数 **20**"、`tests\*.js` 实为 **22 个**。⇒ **"退役后权威数字怎么算"没有落点**。
2. **"真实缺陷数"这一把尺子对某一类门禁天然不公**：`copy-check`（界面文案 ↔ 需求条款）首轮即 **21/0**，命中率**结构性地接近 0** —— 它的价值是"**防误改**"（改了文案就红），而不是"抓缺陷"。
3. **最贵的一道不是候选淘汰那三道**：`harness-check` 成本/体积/自身事故均第一，但 `ADR-0010` §三已**实测否掉"拆分"**。

## 决策

### D1（**分层口径 ＝ 三分**，唯一真源）

门禁体系**只有三种身份**，每一道必须**显式归位**，且"**道**的数量口径**以 `run-all.js` 的 `SUITES` 为唯一真源**"：

| 身份 | 定义 | 是否计入**权威区**（`tests\README.md` 第三节的逐脚本条数与合计） | 现役成员 |
| --- | --- | --- | --- |
| **受管门禁** | 在 `run-all` 的 `SUITES` 里、有断言、会按退出码契约判定者 | **计入** | 17 道（清单＝`SUITES`，逐脚本条数＝实跑通过数） |
| **基建判定项** | 被 `run-all` 调用或独立运行、但**不产出"通过 N 项"断言三元组**者 | **不计入** | `preflight`（环境体检，退码 0/2/3）、`capture-baseline`（产物生成器）、`run-all` 自身 |
| **元机制** | **操作/审计门禁体系自身**的工具（写台账、同步声明、渲染台账） | **不计入**，且**不新增**（见 D3③） | `tests\sync-authority.js`、`tests\lib\*`（夹具层） |

**配套口径**：`tests\README.md` 第三节的**门禁行集合必须 ↔ `SUITES`**（**非门禁项**——基建判定项与元机制——**允许并应当**在该表另列，但**必须逐行标明身份**，不得混进"门禁"的行集合）；任何"脚本总数 N"式的自述**必须写明它含哪些非门禁项**（否则就是 `E51`／`E190` 那一族的"无人守的叙述性数字"）。

### D2（**记分方式**：两类门禁两把尺子）

- **抓缺陷型**（绝大多数门禁）：记"**抓到的真实缺陷数**" —— **只记实跑拦下、且事后确认为真**的问题，逐条附证据指针（`文件:行号`／债号）。
- **防回潮/防误改型**（`copy-check`、以及一切"改了受管物就红"的静态守护）：**豁免**上面那把尺子，改按"**覆盖密度**"登记（它守住的条款数／文案数／字段数）。
  **硬规则**：**不得**仅凭"真实缺陷数 ＝ 0"判这类门禁淘汰；要淘汰它，必须给出**替代守护面**或**显式接受覆盖降级**（后者需负责人签字）。
- 清单**逐轮更新**，但"连续 N 轮为 0"里的 **N 与"轮"的界定**须由负责人另行裁定（本 ADR 只定尺子，不定 N）。

### D3（**退役判据与动作**）

1. **候选产生**：按 D2 的两把尺子逐道判定 → `保留`／`观察`／`候选淘汰`，逐道写**判据缺口**（"要判它可退役，还缺哪一条机器判据"）。
2. **淘汰动作归负责人**：候选清单**只出清单、不执行淘汰**；淘汰须由负责人逐道裁定。
3. **未立判据不新增**（承接 `E57③`）：**判据未立之前不新增门禁脚本与元机制** —— 除非它**刚拦下一个真实缺陷**（本条的例外由"那道门禁自己的战果"承担举证）。
4. **退役留痕**：**退役脚本必须从 D 组（已闭合）移出并在权威区留痕**（承接 `后续路线图.md` 的既有口径），且同批更新 `SUITES` 与 README 第三节。
5. **瘦身 ≠ 淘汰**：对"成本最高但守护面不可替代"者（现为 `harness-check`）单列 **"瘦身候选（非淘汰）"**，其手段是 `ADR-0010` 的 **D3/D4**（输入面登记 ＋ 绿态缓存 ＋ 按需档标注），**不是**删断言。

### D4（**排期**）

- **`E57` 收口**：本 ADR 即为它的收口依据；清单第一版已交付，**残余（淘汰判据的 N、逐道裁定的动作）归负责人**。
- **`E193`（`ADR-0010` D3/D4）与 `E57` 同批**，**D3 先行**（输入面登记表 —— 它可直接复用 `tests\sync-authority.js` 的**锚点/区间写入机制**，不必新造写入器）。
- **冻结面约束（硬）**：**凡需动 `tests\lib\**` 或 `tests\stress-check.js` 的部分，必须等 7 天泡机窗口结束**（冻结点 `592ba70`）。
- **✅ 已解冻（2026-10-19）**：7 天泡机窗口 **2026-10-08 11:31:25 → 2026-10-15 11:31:25（北京）已满**，现场台账经 `--verify-soak` 判 **5/5、失败 0、exit=0** ⇒ 上述硬条件**已满足**；**负责人 2026-10-19"按建议执行"放行解冻**。⚠ **交付版另有一条**：解冻后若 `src`／`server` 有改动，**AC-07 不再自动适用于新版**，须在**交付候选版**上重跑一轮 7 天（见 `tests\README.md` §5.4 与 `项目记录\解冻后首批实现清单-2026-10-19.md` §四）。

## 被否方案（留档）

| 方案 | 否决理由 |
| --- | --- |
| 按"真实缺陷数"一刀切淘汰 | 对**防回潮/防误改型**门禁结构性不公（`copy-check` 首轮 21/0 即为例）⇒ 会先淘汰掉"**只会静默失效、不会主动报警**"的那一类守护 |
| 现在就删掉三道候选（`copy-check`／`screenshot-diff`／`overlap-check`） | 判据未立（D3③）；且三道的**零命中原因各不相同**（设计态白名单化／陈旧候选图／防误改型），不能一锅端 |
| 拆 `harness-check` | `ADR-0010` §三已**实测否掉**（拆分后覆盖与可作证性双降） |
| 把"道"的判定写进脚本自动推导 | 三分的**身份**是**管理口径**（谁计入权威区），不是能从源码推出来的事实 ⇒ 由本 ADR 显式声明 ＋ 由台账逐道标注 |

## 后果

- **好的**：`E57` 有了可执行的判据与动作口径；"道"的数量口径唯一；防误改型门禁不再被误杀；`harness-check` 的瘦身有了归口（`E193`）。
- **代价（如实记）**：①"防回潮型按覆盖密度登记"这条**目前没有机器判据**（覆盖密度靠人工从 `tests\README.md` 与脚本注释里抄）⇒ 属"**纪律 + 评审**"层，不得冒充成"机器守着的"；②三道候选淘汰门禁**在本 ADR 之后仍是绿的**（退役动作未执行），权威数字**不变**；③"连续 N 轮为 0"的 N 仍未定 ⇒ 候选清单**只能给累计命中数**，不能自证"连续 N 轮"。
- **真源**：本 ADR 只定口径；**门禁数字的真源仍是 `tests\README.md` 第三节**，其自洽由 `tests\sync-authority.js --check`（漂移 0）与 `run-all` 收尾的权威对账守着。
