## D1（决策）：凭证存储＝新增表 `auth_credential`，哈希＝Node 内建 `scrypt` + 每口令独立随机盐

- DDL 写入 `schema.sql`（新建库的结构正本），并按 **ADR-0006 D2** 同步升 `SCHEMA_VERSION '4' → '5'`（"改 schema 未升版本"已有指纹门禁拦截）：

```sql
/* ---------------- NFR-14 / FR-8.4 设置页口令凭证表 ----------------
   只存派生值与状态，**永不存明文**；本轮只有一行 username='admin'（设置页口令），
   唯一键按 username 设计，为将来"操作人/管理员分权"留位，不提前实现。 */
CREATE TABLE IF NOT EXISTS auth_credential (
  id           INTEGER PRIMARY KEY AUTOINCREMENT,
  username     TEXT NOT NULL,                   -- 本轮恒为 'admin'
  algo         TEXT NOT NULL,                   -- 'scrypt'
  params       TEXT NOT NULL,                   -- 'N=16384,r=8,p=1,keylen=32'
  salt         TEXT NOT NULL,                   -- 16 字节随机盐（hex）
  hash         TEXT NOT NULL,                   -- 派生密钥（hex）
  fail_count   INTEGER NOT NULL DEFAULT 0,      -- 连续失败次数（落库 ⇒ 重启不清零）
  locked_until TEXT,                            -- 锁定截止（本机时间文本，DR-16；NULL=未锁定）
  is_initial   INTEGER NOT NULL DEFAULT 0,      -- 1=由初始化码设置、人工尚未改过
  created_at   TEXT NOT NULL,
  updated_at   TEXT NOT NULL,
  changed_by   TEXT,
  team_code    TEXT,                            -- 与 op_log 同源：改密时当前生效班次的班组
  UNIQUE(username)
);
```

- 派生：`scryptSync(password, salt, 32, { N: 16384, r: 8, p: 1 })`（`node:crypto` 内建，**零 npm 依赖**，守 ADR-0001/0002）；比较一律 `timingSafeEqual`。
- **任何位置不得出现明文或可逆值**：库里、日志里、`op_log.content` 里、导出的库里、错误信息里。缓冲区用后清零（`buf.fill(0)`），口令不回显（`type="password"`）。
- 口令口径：**4～64 位**，不强制字符集（现场口令不是账号体系），但**不得**与用户名相同；改密时**不得**与原口令相同。
- 表按多行设计（唯一键 `username`），本轮只写 `admin` 一行。

## D2（决策）：错误次数限制——连续 5 次锁定 5 分钟，成功即清零，全程留痕

- 配置真源＝`board.config.js` 的 `server.ifAuth.{ maxFailures: 5, lockMinutes: 5, sessionHours: 12 }`（W5-② 补 `server` 段时一并写入；服务端优先级仍为 内置默认 → `board.config.js` → 环境变量 → 命令行）。
- 计数**落库**（`fail_count` / `locked_until`）：**进程重启不清零**（否则重启即绕过限制）。
- 锁定期间**即使口令正确也拒**：`423 { ok:false, error:'locked', retryAfterSec }`；`retryAfterSec` 由注入时钟算出。
- 对外错误**不区分原因**：口令错与用户不存在一律 `401 { ok:false, error:'bad_credentials' }`；库内与日志里如实记录。
- 登录失败、触发锁定各写一条 `op_log`（`op_type='解锁失败' / '账号锁定'`、`result='失败'`、`content` 含来源 IP）；成功登录写 `op_type='解锁'`、`result='成功'`。
- 来源 IP 取 **`req.socket.remoteAddress`**，**不信任何请求头**（`X-Forwarded-For` 之类可伪造）。
- 时间一律走**注入时钟**（ADR-0003 **D17**：业务代码不得裸 `new Date()` / `Date.now()`）。

## D3（决策）：会话令牌——256 bit 随机、仅存服务端内存、`Bearer` 传递、滑动续期

- 登录成功返回 `{ ok:true, token, username, expiresAt }`；`token = randomBytes(32).toString('hex')`（256 bit）。
- **只在服务端内存**（不落库、不落盘）；客户端以 `Authorization: Bearer <token>` 回传。
- TTL 默认 **12 h**（`sessionHours`），**滑动续期**，但绝对上限 **24 h**（防"一直用就一直有效"）；`POST /auth/logout` 立即失效；**进程重启即全部失效**。
- **与 IF-A 的静态访问令牌严格分开**：`server.ifAuth.token`（W2 已落地，供 MES/上位机侧调用）**不得**用于看板解锁；会话令牌**不得**用于 IF-A 授权；两套中间件互不复用，比较都用 `timingSafeEqual`。
- 前端保存位置：**内存 + `sessionStorage`**（关窗即弃）；**不得**落 `localStorage`（长期驻留）。

## D4（决策）：初始口令与重置——**不设默认口令**，走「本机回环 + 一次性初始化码」

- 无凭证行 ⇒ 服务处于**未初始化**态：`POST /auth/login` 一律 `409 { ok:false, error:'not_initialized' }`，提示走初始化。
- `POST /auth/init { code, password }` 是**唯一**初始化入口，两条硬约束：
  1. 请求**必须**来自回环（`req.socket.remoteAddress ∈ { '127.0.0.1', '::1', '::ffff:127.0.0.1' }`，**只看 socket**，不看任何请求头）；
  2. `code` 必须是**本次进程启动时**生成的一次性初始化码（`randomBytes(6).toString('hex')`）：启动时打印到控制台、写 `op_log`、**仅存内存**、成功后立即作废、进程重启重新生成。
- **重置**＝删除 `auth_credential` 行后重启（同样需本机 + 新的初始化码）；**不提供**任何远程重置/找回通道，**不设**"万能口令"。
- 明令禁止：出厂默认口令（`8888`/`admin`/`123456` 之类）进入服务端口径。演示口令 `8888` **只允许存在于演示模式**（D5）。

## D5（决策）：演示模式不拦截、真实模式强制登录、前端不碰哈希

- `dataSource:'mock'`（演示/培训）**不启用**登录拦截，界面**显式提示**"演示模式：未启用服务端口令校验（口令由服务端校验）"——延续 E34/E38/E39 的"**显式降级**"口径（不静默、不假装已登录）；此模式下 `mockData.js` 的 `unlockPassword:'8888'` 保留为演示口令。
- 服务端模式（真实源）**强制**登录：未登录/令牌过期 ⇒ `401` ⇒ 前端**显式降级**（提示"未登录或登录已过期"，**不黑屏、不抛未捕获异常**）；FR-8.2 的"5 分钟无操作自动锁定"到点后**同步**调 `logout`，令牌即失效（**前端计时器与服务端令牌不各管一套**）。
- 前端**只做三件事**：提交口令、保存令牌、统一处理 401。**不得**在浏览器里做哈希、比对、错误计数、锁定判定；现状 `SettingPanel.js` 的本地明文比对**必须删除**，改为调用 `POST /auth/login`。
- 改密 UI（FR-8.4）：设置页"修改密码"（原口令 + 新口令 + 确认），成功后**强制**清当前会话并要求重新登录。

## D6（落地约束与验收口径）

1. 新表 ⇒ `schema.sql` + `SCHEMA_VERSION` 同步升位（ADR-0006 D2）；新表为**纯新增**，旧库 `CREATE TABLE IF NOT EXISTS` 幂等生效，不做重建迁移。
2. 断言必须覆盖（写进 `tests\db-check.js`，每条**行为级**、遵 ADR-0004 D23 反静态防空洞）：
   - **哈希非明文**：库里 `hash`/`salt` ≠ 口令本身；同口令**两次改密**盐与派生值都不同；同口令同盐派生可复现（证明是确定性函数而不是随机占位）。
   - **错误次数限制**：连续 4 次失败仍可成功登录（第 5 次成功即清零）；连续 5 次失败后**即使口令正确也拒**且带剩余秒数；锁定到期（注入时钟推进）后恢复；**重启进程不清零**。
   - **令牌**：随机性（两次登录 token 不同）、过期、`logout` 即失效、进程重启即失效；缺失/伪造令牌一律 401。
   - **未初始化态**：非回环请求**即使带对码也被拒**；错码被拒；对码 + 合法口令成功且码**立即作废**（第二次用同码失败）。
   - **演示模式**：演示模式下不拦截（正向）；服务端模式下未登录被拦（负向）——**成对断言**。
   - 每条判据都要有对应的 **D22 定点变异**并**指名**变红的断言。
3. `op_log` 留痕：初始化、登录成功、登录失败、账号锁定、改密、登出各一条，可审计（含操作人与班组编号同源口径）。
4. 本 ADR **不改需求原文**：`NFR-14` 的"哈希存储/可修改/错误次数限制"与 `FR-8.4` 的"可重置"逐项由 D1/D2/D4 对应；若实施中发现与需求冲突，**先停下升级**。

## D7（被否方案）

| 方案 | 否掉的理由 |
| --- | --- |
| 前端保留口令比对（现状 `unlockPassword:'8888'` 明文） | 直接违反 `NFR-14`「哈希存储」：要下发口令到浏览器才能比对＝明文分发；"错误次数限制"在前端按 F5 刷新即可绕过 |
| 库内存明文，或 MD5/SHA-1 单轮哈希 | 明文违反 NFR-14；单轮快速哈希对 4 位口令可秒级枚举 —— 本项目口令短，必须**慢哈希 + 每口令独立盐** |
| 出厂默认口令（`8888`/`admin`/`123456`） | 现场无人改密即长期有效；且默认口令必然写进交付文档，等于公开 |
| 令牌落库 / 落盘 | 多一处"拷走即可冒充"的凭据；本轮无多实例需求，内存态足够，**重启失效反而是安全属性** |
| 复用 IF-A 静态令牌做解锁 | 静态令牌在配置里、给外部接口用，泄露面完全不同；混用会让"对外接口凭证"变成"看板管理员凭证" |
| 前端会话令牌放 `localStorage` | 长期驻留、本地翻取成本低；`sessionStorage` 关窗即弃更契合"单人本机操作"（FR-8.1 口径） |
| 自签 `jwt`（或引入 `bcrypt` 等依赖） | 破坏零 npm 依赖（ADR-0001/0002）；且"重启失效/登出即失效"用随机串 + 内存表更简单、更严格，反而不用额外吊销名单 |

## D8（落地细化，2026-09-28 主代理复核确认；不改 D1–D5 的任何口径）

实现阶段报出 6 处需要明确的边界，逐条裁定如下（均为 D1–D5 在真实调用点上的**细化**，不是口径变更）：

| # | 细化 | 理由 |
| --- | --- | --- |
| ① | **第 5 次失败当场返回 `423 locked` + `retryAfterSec`**（不必等第 6 次才知道被锁） | D2 已定"连续 5 次失败锁定"；第 5 次即是进入锁定态的那一次，返回锁定态才是如实反馈 |
| ② | **锁定期满不自动清零计数**：期满后再错**一次**即立刻重新锁定；只有**成功登录**才清零 | D2 原文"成功即清零"；清零条件只有一个（成功），期满只是"可以再试"，更抗暴力枚举 |
| ③ | 一次性初始化码的 `op_log` 登记**只在"未初始化"态**写 | 已初始化时 `POST /auth/init` 一律 `409`，此时再写码只会制造噪声与误导 |
| ④ | 改密**清该用户全部在途会话**（不止当前会话） | D5 要求"清当前会话并要求重新登录"；单机单人下两者等价，取**更严**一侧不损失任何东西 |
| ⑤ | **非回环来源的拒绝**在 HTTP 端到端层造不出来（本机 fetch 恒为回环）⇒ 该判据由**服务层探针**覆盖 | 如实标注覆盖层级；不得因为"HTTP 层测不到"就把该判据降级为声明 |
| ⑥ | 旧库 `op_log` 尚无 `team_code` 列时，"迁移前备份"这条审计走**兼容插入**（`audit.compat=true`、`team_code` 留 `NULL`） | E18 的备份审计必须能在**旧库迁移当下**写成；该兼容路径**只作用于这一条留痕**，不改变正常留痕的列语义 |

| ⑦ | `/auth/status` **无需鉴权**即可返回 `locked`/`lockedUntil`/`lockedUnknown`/`isInitial`/`sessions`/`initCodePending`（**不含任何秘密**） | **登记备查**：若将来要求"连锁定态也不外泄"，**必须先改本 ADR**，不得在实现里单方面加口径 |
| ⑧ | 口令长度按 **UTF-16 码元**计（4–64）且**接受 `\u0000`**（行为自洽；D1 未禁止控制字符） | **登记备查**：要收紧（按码点计长 / 禁控制字符）**必须先改本 ADR** |
| ⑨ | `locked_until` 的"不可解析"口径**统一为从严**：**`NULL` ＝未设置**（正常未锁定）；**非 `NULL` 且不可解析（含空串 `''`）一律＝"锁定未知" ⇒ `login 423`**；**纪元 0**（如 `1970-01-01 08:00:00`、`'0.0'`）属**可解析**（已过期）⇒ 放行 | 结案复跑 R1/R2 查出两处不一致（纪元 0 被当真值判断误判成"未知"；空串走 fail-open 放行）。**只有一条规则更好守**：不可解析就拒绝，库被写坏时不放行 |
| ⑨-注 | **`'0'` 与 `'0.0'` 的区别（免后人误判）**：`'0'` 被日期解析器解释为 **2000-01-01**（可解析且在过去）⇒ **过期放行**；只有 **`'0.0'` 这类纯数字串**（日期解析抛错）才走"毫秒时间戳"回退 ⇒ 纪元 0 ⇒ 也放行。即：**两者都放行，但走的是不同分支**；**不**为 `'0'` 增加"纯数字优先"规则（否则会与"日期解析优先"冲突） | 主代理 2026-09-28 裁定（W5-③ 提问） |

**另记一处实现取舍（与 ADR-0006 的分工一致）**：`initSchema()` 是**同步**调用点，而 `node:sqlite` 的 `backup()` 只有异步形态；为免"把同步入口改成 async ⇒ 未捕获 rejection ＋ 迁移照跑"（**恰是 E18 要禁止的静默继续**），`server\db\maintain.js` 新增**同步入口 `backupToSync()`**（`VACUUM INTO`，目标已存在即报错 ⇒ 天然不覆盖），与异步 `backupTo()` **共用同一套**命名/保留/`flushWal`；两形态产物等价性由断言 `E44⑤` 作证。

## D9（被否方案）

| 方案 | 否掉的理由 |
| --- | --- |
| 把 `initSchema()` 改成 `async` 以便用异步 `backupTo()` | 调用点（`server\index.js` 与各夹具）会变成"未捕获 rejection ＋ 迁移照跑"，正是 E18 禁止的静默继续；`VACUUM INTO` 已能给出等价的一致备份 |
| 同刻备份用"自增序号"而非毫秒 | 自增需要跨进程持久化状态；毫秒可由**注入时钟**直接给出、字典序仍＝时间序（E44 的根因是"同秒覆盖"，毫秒＋1 ms 探测已足够） |

## 证据
