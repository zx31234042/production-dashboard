# 架构决策记录（ADR）

> **用途：** 记录"为什么这么定"的架构决策，避免几个月后有人（包括我们自己）回头推翻已有取舍。
> **维护规则（2026-09-19 细化，P3-1：原文只说"不改"，未给"纯勘误"留出口，实际也已被违例修改过 3 次）：** 一个决策一个文件，编号递增。**三类改动分开对待**：
> 1. **索引与状态标注**（`README.md` 索引行、主 ADR 头部"状态"、指向后续 ADR 的承接行）—— **允许直接改**，这是台账不是决策；
> 2. **纯勘误 / 落地标注**（错别字、失效路径、待办项已完成、证据数字更正）—— **允许改，但必须在本文件"勘误与落地记录"里登记一行**（改了什么、为什么不算决策变更）；
> 3. **决策变更**（结论、取舍、被否方案）—— **必须新写一条 ADR**，并把旧的标 `已取代（由 ADR-XXXX 取代）`。
> **证据与核查过程放附件**，结论仍写在主 ADR 里、不重复。
> **命名：** 主决策 `ADR-<四位序号>-<主题>.md`；**主题可用中文**（现有四条均为中文，规则与实情一致）；附件 `ADR-<主决策序号>-附件-<主题>.md`。
> **编码：** UTF-8（无 BOM），换行 CRLF，与 `项目记录\` 其余文档一致；本目录**只放 `.md`**，不做 Word 版本。
> **建档日期：** 2026-09-19
