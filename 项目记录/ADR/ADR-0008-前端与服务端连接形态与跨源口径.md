# ADR-0008：前端与看板服务端的连接形态、跨源口径与服务端模式下的职责边界

| 项目 | 内容 |
| --- | --- |
| 编号 | ADR-0008 |
| 状态 | **已接受**（2026-09-28，规划主代理提方案，负责人裁定「选项 A」） |
| 日期 | 2026-09-28 |
| 触发来源 | W5-②（前端切真实源）只读勘察报回**两条硬阻塞**：① `file://` 页面（`Origin: null`）跨源访问 `127.0.0.1` 会被浏览器拦下，而全 server 目录**零 CORS/`OPTIONS` 处理**；② 若不追加决策，"谁向 MES 上报、谁造数"在服务端模式下会出现两套真源。原任务分解（`项目记录\服务层第二笔-任务分解与排期.md`）未覆盖跨源形态 |
| 相关 | 需求 **UI-20**（设置页待补传清单与人工重报入口）、**IF-B.9** / **NFR-10** / **NFR-13**（不自动重试、人工重报）、**AC-06**、**AC-09** / **NFR-25**（不得对外访问）、`server\http\router.js`、`server\index.js`、`src\config\board.config.js`、`src\services\api.js`、`src\main.js`、ADR-0001 D1/D2（双进程开发模式 / 单进程交付模式） |

## D1（决策）：服务端**托管静态前端**，作为首选入口（同源，无 CORS）

- `GET /` ⇒ `index.html`；`GET /src/**` ⇒ `src\` 子树静态资源（`.js/.css/.png/.svg/.woff2` 等，按扩展名给正确 `Content-Type`）。
- **白名单式放行**（不是黑名单）：只有 `index.html` 与 `src\` 子树可读；`需求文档\`、`项目记录\`、`tests\`、`tools\`、`本地归档\`、`输出文件\`、`server\`、`data\`、`.git` **一律 404**，且响应体**不得**包含被禁文件的内容。路径穿越（`..`、`%2e%2e%2f`、绝对路径、反斜杠形态）必须有断言覆盖。
- 静态响应 `Cache-Control: no-store`（开发期改前端后不应看到旧文件；不引长缓存）。
- 未命中白名单的路径仍走既有 JSON 404 形状，**不返回 HTML**。
- 理由：**消掉 CORS 这个失败面**。双击 `index.html` 依赖浏览器跨源策略，而 `http://127.0.0.1:8787/` 是同源访问，`EventSource`、`fetch`、`POST` 预检全都不存在；kiosk 与将来的交付壳（ADR-0001 D2）都可以直接指向它。

## D2（决策）：`file://` 双击方式**保留**，但 `null` 源只在**回环绑定**下放行

- CORS 白名单**只有**：字面量 `null`（`file://` 页面的 `Origin`）＋ `http://127.0.0.1:<实际端口>` / `http://localhost:<实际端口>`（端口取**实际监听端口**，不写死 8787）。
- **`null` 的前提是"监听地址为回环"**：绑定 `127.0.0.1`/`::1`/`localhost` 时才回 `Access-Control-Allow-Origin: null`；**绑定非回环地址时一律不回任何 CORS 头**（跨源被浏览器拦下）——这堵住"对外暴露 ＋ 允许 `null` 源"这个最危险组合，与 `NFR-25`/`AC-09` 一致。
- 允许方法 `GET, POST, OPTIONS`；允许头 `Content-Type, Authorization`；**绝不**回 `Access-Control-Allow-Credentials`（本项目用 `Bearer` 头，不用 Cookie，允许凭据只会扩大攻击面）。
- 非白名单源 ⇒ **不回** CORS 头（由浏览器拦下），服务端不因此报 5xx、不写 `console.error`（避免踩"无红色报错"门禁）。
- **已知残余风险（明示接受）**：允许 `Origin: null` 意味着本机任意本地 HTML 文件也能读看板接口。接受理由：服务只绑回环、现场机不连外网（`NFR-25`）、单机单人操作，且**已禁用凭据型跨源**；若将来改为对外监听，D2 前提自动失效（那时不再回 CORS 头）。

## D3（决策）：服务端模式下的职责边界——**数据真源＝服务端，前端不造数、不直接向 MES 上报**

- **数据真源**：`GET /state` 的快照 ＋ `GET /events` 的增量（`frame/link/task/standard/upload/warning`）。前端在服务端模式下**只应用、不生成**：`M.tick()` 一类的本地逐秒造数（`src\services\mockData.js`）**不得**在服务端模式运行。
- **上报 MES 由服务端独占**：13 字段由 `server\services\uploadReporter.js` 从 `measure_rt` 装配（W4 已落地），失败落 `upload_log`、**不自动重试**、唯一人工入口 `POST /upload/retry`。前端在服务端模式下**不得**再调用 `Api.uploadReport` / 上报定时器（否则同一件任务会有两条上报路径，`uploadId` 相同虽可幂等去重，但"谁负责、谁留痕"会分裂）。前端保留报文组装函数**仅供演示模式与跨实现对账断言**使用。
- **人工重报入口按需求落在设置页**：`UI-20` 明确要求"**在设置页**提供待补传清单（条数、接口名、时间、失败原因）＋ 按序/批量重报 ＋ 重报动作与结果写操作日志"。故 W5-② 必须在设置页新增该卡片，并**重拍** `08-操作设置` 截图基准（人工过目确认）。
- **尚未接入服务端的模块**（公告 `notice`、维保 `maintenance`、异常台账 `alarm`、`selfCheck` 细项、`opLog`）：服务端模式下一律**显式无数据（`—` / "尚未接入服务端"）**，**不得**用演示值顶替（延续 E34/E38/E39 的"显式降级"纪律）；它们的真实接线属后续包。
- **缺失值口径统一**：数值缺失一律 `null`，**绝不用 `0` 顶替**（W4 已定）；前端未加守卫的 `.toFixed()`（`DeviceStatusPanel.js`、`TaskPanel.js`）必须补守卫，`buildReportPayload` 的 `?? 0` 改为 `null`，`noDataStats()` 逐键由 `0` 改 `null`（保留 `noData` 位并仍最后赋值）。

## D4（决策）：默认数据源仍为**演示模式**，服务端源显式开启、失败自动回退

- `board.config.js` 的 `dataSource` **默认保持 `'mock'`**：`screenshot-diff`（10 张基准）、`ui-check`、`browser-check` 的既有基线全部建立在"默认 mock、首屏必出两位小数实测值"之上（`tests\capture-baseline.js` 的冻结时钟 + 种子随机 + 定时器置空）。
- 服务端源通过**显式开关**进入：`?source=server`（与既有 `?source=upper` 同形）＋ 配置键；**失败/未就绪时优雅回退演示源**（`console.warn` + 现有降级横幅，**只出现一条**、不与既有 `.degraded-banner` 叠加；**绝不** `console.error`、绝不抛未捕获异常）。
- 提供**只在服务端模式可见**的"数据源"角标（演示模式下不出现 ⇒ 不影响任何截图基准）。
- 理由：把"真实源"设为默认会让 20 个门禁脚本里的基线类断言集体变红，且现场演示/培训仍需一键可用的演示数据（W5 交付说明里"保留演示模式作为降级/培训用"）。

## D5（被否方案）

| 方案 | 否掉的理由 |
| --- | --- |
| 不加 CORS，靠"部署时把页面放到同源"的纪律 | 双击 `index.html` 是**当前既有的评审与自测方式**（`?tab=/?link=off/?unlock=1/?source=upper` 全在 `file://` 下用），没有 CORS 就当场失效；把失败留给部署纪律＝把不可验证的风险留给现场 |
| `Access-Control-Allow-Origin: *` | 对本机服务等于向任意网页开放（含恶意站点脚本）；且 `*` 与凭据互斥、语义最粗，无法体现"仅回环"这一前提 |
| 允许 `null` 源但**不**限定回环绑定 | "对外监听 ＋ 允许任意本地文件跨源读接口"是最坏组合，直接违反 `NFR-25`/`AC-09` 的取向 |
| 前端继续独立向 MES 上报（保留浏览器队列为真源） | 与 W4/E10 的"服务端独占上报 + `upload_log` 单源"冲突：两条路径状态会漂移，人工重报清单会分裂成两份 |
| 服务端模式下用演示值填充"尚未接入"的模块 | 违反"前端不再自行造数"与显式降级纪律；界面上真实值与演示值无法区分，等于假数据 |
| 默认切到服务端源 | 保护不了基线类门禁（截图/ui/browser），且服务端不在场时首屏即空 |

## 证据

- 实现：`server\http\cors.js`（或 router 内等价实现）、`server\http\static.js`（静态托管白名单）、`server\index.js`（`mountSSE({bus, snapshot})` 真实装配）、`src\services\boardSource.js` + `src\services\stateAdapter.js` + `src\components\UploadPanel.js`（前端切源与 UI-20）、`src\config\board.config.js`（`board` 与 `server` 段）。
- 门禁：CORS 八条、静态托管四条路径穿越、服务端源降级与"不造数"、UI-20 卡片与 `op_log` 留痕，均须行为级断言 ＋ **D22 定点变异指名变红** ＋ **SHA-256 字节级还原**。
- 人工确认：`08-操作设置` 截图基准重拍后由负责人过目；4K kiosk 下新卡片排版与降级横幅需人眼确认（`overlap-check` 覆盖三档分辨率）。
