## 一、问题（事实，2026-10-02 主代理实测）

`schema.sql` 建表 **15** 张，其中**恰 5 张**的 `INSERT` 与 `FROM` **均为 0**：`shift_stat`、`alarm`、`warning`、`maintenance`、`notice`。

> **登记更正**：`E62` 行原文写"按 `schema.sql` 的 **16** 张表逐表统计"；主代理实测 `CREATE TABLE IF NOT EXISTS` 为 **15** 张（差 1，待核）。**不影响结论**：零写入点的表恰为上述 5 张。

**后果（按需求条款）**：

| 表 | 需求 | 后果 |
| --- | --- | --- |
| `shift_stat` | DR-06（备注写"班次结束时固化"） | `DR-17`「累计运行」**名不副实**：跨班不清零、跨零点归属失效；`server\services\stateSnapshot.js` 只能写 `addRunSec: 0` |
| `alarm` | DR-07 | `FR-5.12/5.13`（异常闭环、当班异常台账上限 8 条）在服务端模式下**无持久化载体** |
| `warning` | DR-08 | 判定产出的预警**经 SSE 发出后不落库** ⇒ 无预警历史 |
| `maintenance` | DR-09 | `FR-6` 维保台账：录入**只写浏览器内存**（`README.md`「已知限制」第 2 条） |
| `notice` | DR-10 | `FR-7` 公告备注同样只在内存 |

同时：`tests\trace-check.js` 现状把这些记为 **`covered-indirect`**，依据**只是 `db-check` 的"建表与结构"断言** —— 按 **ADR-0004 D19**，**不得读成功能已覆盖**。

## 二、决策

### D1（Q1 ＝ A1：分批接线，先落两张"纯服务端事实"表）

**"库为唯一真源"这一原则本次只落两张表**：

1. **`shift_stat`**：**班次边界到达时固化上一班**（DR-06 的 14 列在 `schema.sql` 已就绪，**不改表**）；
2. **`warning`**：在**判定发布点**（`server\index.js` 的 `emitWarnings()`，即 `ingest` 的 `onSampled` 采样落库之后）**同批落库**。

这两张**不需要新增 HTTP 路由、不需要人工输入、不依赖三方答复** ⇒ 可立即开工。

### D2（Q2 ＝ B2：人工录入类维持演示态，但必须"显式未接入"）

`maintenance`／`notice` **不新增 IF-E 写路由**，继续由前端演示态内存承载；但在**服务端模式下必须显式标注"未接入"**（与 `src\services\selfCheckProbe.js` 的既有口径一致：**服务端没有的字段明确"未接入"、不造数**）。`alarm` 的报警生成与人工闭环**同批暂不落库**。

**连带义务（必须同批）**：`tests\trace-check.js` 的相关归属**如实改判**（不得再用"建表断言"充当间接覆盖）⇒ **可追溯覆盖率与离线覆盖率数字会下降**。这是**诚实反映、不是回归**，收口时须在权威区与本 ADR 一并写明。

### D3（Q3 ＝ 触发点① ＋ 授权重设 `addRunSec` 上界）

1. **固化触发 ＝ 服务端 tick 里检测"跨班"后固化上一班**：与现有 **1 s 采样同拍**，**不新增定时器**（沿用 `selfCheckProbe` 的"节流而不新起定时器"工程约定）；**跨班时刻被跳过时，下次采样补记**（补记口径须可测）。
2. **授权重设** `server\services\stats.js` 的 `addRunSec` 上界：现行校验 `0 ≤ addRunSec ≤ runSec` 会让"无采集串且无「测试中」件"时**任何非零增量都被拒收**（`E68` 修复把分档由 3 档收窄为 2 档后，连 n=1 都拒收）⇒ **`shift_stat` 一旦接线即爆**。

## 三、被否方案与理由

| 方案 | 内容 | 否掉的理由 |
| --- | --- | --- |
| **A2** | 五张表一次全接（含人工录入与报警闭环状态机） | `alarm` 依赖 **`Q-12`** 故障字典、`maintenance` 依赖 **`Q-13`** 维保周期与耗材判据（**均归上位机方、至今未回**）⇒ 现在接＝接空壳；且需新增写路由，牵动路由数与静态白名单门禁，成本大 |
| **A3** | 完全不接，只把 `trace-check` 归属如实降级 | 零成本，但 FR-5.12/5.13、FR-6、FR-8 在服务端模式仍是"界面有、库没有"，与 7×24 无人值守口径相冲。**本次仅把它用于 D2 覆盖的三张表**（降级部分照做） |
| **B1** | 人工录入新增 IF-E 写路由 ＋ `op_log` 留痕 | 需求侧 `Q-13` 未回 ⇒ 录入口径与校验规则未定，做完也可能返工；留待答复后**另开 ADR** |
| **B3** | 用 `op_log` 单表承载维保/公告 | 把业务事实混进审计表；DR-09／DR-10 的追溯归属说不清 |
| **C2** | `shift_stat` 用专用定时器到边界固化 | 与"不新起定时器"的既有工程约定冲突，且多一条时间真源 |
| **C3** | 只在边界时刻固化（不允许补记） | 服务端重启/卡顿错过边界即**永久漏固化**，累计运行会静默少算 |

## 四、落地时必须一并做的（后果）

1. `stats.js` 的 `addRunSec` **重新设计校验语义**（不是放宽成不校验）：需给出新的上界依据，并配**可证伪断言**（旧上界下必红、新上界下必绿）＋ **D22 定点变异**。
2. `stateSnapshot` 的 `addRunSec` 取值改为**从 `shift_stat` 读上次累计**；`DR-17` 的日/月/年累计改为**对 `shift_stat` 求和**（含跨零点、跨月归属）。
3. 新增写入点须有**唯一写入口**（沿 `server\repo\result.js` 的 `upsertJudgement()` 先例）＋ 幂等/单调口径 ＋ `/health` 可观测字段（沿 `state.resultWrite{writes,failures,lastError}` 先例）。
4. `trace-check` 归属改判（D2）＋ `tests\README.md` 权威区同步（**覆盖率数字下降**）。
5. **不做**：不改 `schema.sql`（五张表结构已就绪，本决策**不新增列**）；**不升需求版本**（本决策**不增删条款**，259 / P0 188 / AC 12 / Q 7 不变）；不改 `PROJECT_RULES`。
