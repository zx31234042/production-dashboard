## 八、不变式与注意事项（别踩）

1. **提交与推送分工（`PROJECT_RULES` 第六章，2026-09-19 v1.16 修订）**：**AI 协作方执行本地 `git add`/`git commit` 并自行生成、核对提交信息；`git push` 一律由项目负责人人工执行** —— AI **不得** `git push`/`pull`/`fetch`/改写历史；提交后用 `git commit -F <信息文件>`（禁用 `-m`），信息文件放忽略路径、用完即删；提交后报告提交号与信息全文并提示"待人工 push"；
2. **甲方原件（`来源文件\`、`reference\`）不进版本库**，仓库保持私有；
3. **`.ps1` 脚本必须存为 UTF-8 带 BOM**，否则生成文档的中文字体名会乱码；
4. **前端不使用 ES module**（保证双击 `index.html` 可打开），继续用普通 `<script>` + 全局命名空间；
5. **不引入第三方库、不使用 CDN**（内网隔离要求，NFR-25）；
6. **改了 `.md` 要重新生成对应 `.docx`**；**改了界面要重新生成 `src\assets\screenshots\`**（4K 交付截图用
   `node tests\capture-baseline.js --size 3840x2160 --out src\assets\screenshots`，基准图用 `--update`）；
7. **需求清单改动必须升版本号**，旧版移入 `需求文档\历史文件\`；
8. **docx 打包必须用 OPC 正斜杠条目名**（`tools\md2docx.ps1` 与 `md2docx-img.ps1` 已改；不要再退回
   `ZipFile::CreateFromDirectory`，它在 Windows 上会写成反斜杠）；
9. **用户输入拼 HTML 前必须过 `Format.esc()`**（公告正文、检修内容/责任人、操作日志明细）；
10. **门禁数字的权威值在 `tests\README.md` 第三节**，改脚本或改界面后必须同步那一段与 `项目记录\`；
11. **提交信息规则（`PROJECT_RULES` 6.1，2026-09-19 v1.14 修订）**：**一次提交装下本次全部变更** —— **Summary 一行**＝一个 `类型: ` + **≤30 字概括**，**Description**＝按 `类型:` 逐条**分类描述**（跨多个类型时必写）；**绝对不要在一行里塞两个 `类型:`**；GitHub Desktop 的 **Summary 是单行框、回车即提交**，要换行请用 **Description**（`93f27a9` 已踩过，见 6.4）。
12. **多设备用 DSH 同步时，项目文件夹路径必须两台完全一致**（本项目统一用 **`D:\work\vibecoding\production-dashboard`**，无空格）。原理：插件按"工作区 ID"同步，`storages\workspace.json`（**参与同步**）登记了工作区**及其路径**，而「换位置」产生的 `workspace-local-paths.json`（本机路径覆盖）**不参与同步** —— 路径不一致且无覆盖时，插件会按同步来的路径**再落盘一份**，形成同名重复目录。**2026-09-20 已按此处置完毕并闭环**（详见 `工作日志.md` 同日「环境：DSH 同步插件路径分裂」一节）。
13. **文档里的分层/连接关系一律用 Markdown 表格表达，不要用 ASCII 框线图**：框图要求"整行总宽一致"，依赖"中文宽 = 2 × 西文宽"这一字宽假设，而该假设在本项目查看器与 `md2docx` 生成的 Word 里**都不成立**（代码块西文 Consolas / 中文微软雅黑，比值 ≈1.8）⇒ 必错。**例外**：`├──`/`└──` 树状示意是安全的（只需同层级前缀一致）；若改用树状图，**状态与说明必须内联跟在文字后，不得用空格对齐成列**。Mermaid 实测**不被 DSH 文档视图支持**（只在你用 GitHub 看时有效）。
