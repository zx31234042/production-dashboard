## 二、实测确认存在的四种回执形状

| 场景 | 形状 | 关键字段 |
| --- | --- | --- |
| **成功** | `{errcode, __sys__{msg,traceId,detailMsg,msgKey,status}, __version__, Data, resultMsg, __blocks__}` | `errcode = 1`；`__sys__.status = 0`；`Data` 为**数组**；`resultMsg` 为中文结果描述；`traceId` **有值** |
| **业务 / 参数异常** | `{code, message, data, __sys__{msg,status}}` | `code = -1`；`message` 为提示；`data = null`；`traceId` **缺失** |
| **未通过鉴权（含签名错误）** | `{__sys__{msg,traceId,detailMsg,msgKey,status}, __version__, __blocks__}` | `__sys__.status = -1`；`msg` 为英文提示；`traceId` 为**空串** |
| **服务未注册** | `{__sys__{msg,…,status:-1}, __version__, errorMsg, __blocks__}` | `msg` / `errorMsg` 为中文："调用服务id[X]没有注册，无法执行服务调用！"；`traceId` 为空 |

**三者的共同点**：**HTTP 状态码一律为 200**，成败只能由**报文体**判断。

与 MES 方附件《19车间MES与产线设备系统接口定义》§1.3 所写 `{ "status": 1, "msg": "…", "data": {} }` **均不完全一致**；其中**异常形状**（`code`/`message`/`data`）与 MES 方回签件正文批注"可以统一使用 `code`、`msg`"**吻合**，可判断该批注来源于异常分支。

## 三、实测结论（并对应到函件条目）

1. **签名链路可用**：我方以 **Node 零依赖**自行实现的 `SHA1withDSA` + **小写 hex** + `p_password` 冒号 **URL 编码** + 固定私钥，被 MES 平台**接受**（探测 #4/#5/#6 均通过鉴权）。据此，函件 N-14 的 a) / b) / g) 已由我方自证；**时间戳按本机时间、分钟级**亦被接受。
2. **回执结构以实测为准**：三套形状并存，附件 §1.3 需更正（函件 **N-1**）。
3. **`S_ME_BD_0003` 是查询接口**：只发 `workshopNo` 即成功并返回人员列表；按文档"上报"字段发送反而异常 ⇒ 文档请求 / 响应两栏**整段反转**（函件 **N-4**）。
4. **`S_ME_BD_0001` / `S_ME_BD_0002` 方向无误**：我方调用、返回列表；请求参数栏的 `status` / `msg` 属回执字段，实测证明请求只需 `workshopNo`（函件 **N-5**）。
5. **`workshopNo = "19"` 为有效编码**（由 #6 返回数据证实）；#4/#5 返回**空数组**应系测试环境**暂无班组 / 设备数据**，非参数错误。
6. **地址单斜杠与双斜杠均可调用**（#1 与 #2 结果一致）⇒ 文档地址中的 `//fxzg-be` 属**书写瑕疵**，不影响联调，仅需更正文案（函件 **N-6**）。
7. **签名错误与未携带签名不可区分**（#8 与 #1 完全一致）⇒ 排障依赖 `traceId`，但该路径 `traceId` 为空（见函件 N-1 的确认项）。
8. **入参严格校验**：多余字段会触发异常（#7）⇒ 适配层必须**严格按文档字段发送，不得多发**。
9. **地址栏以可见文字为准**（函件 **N-6**）：平台**把 URL 路径段直接当作"服务 id"**（#9 的报错文案为证），故**可见文字即真实服务名**；附件中"接口地址"超链接目标统一指向 `S_ME_MG_0001` 应为**复制粘贴错误**。
10. **双斜杠无害**（#10）：`//fxzg-be/service/...` 带签名调用**成功**，与单斜杠结果一致 ⇒ 属**书写瑕疵**，不影响联调。
11. **"服务名写错"可被明确识别**（#9 有专门文案），而"签名错误 / 未签名"不可识别（#8）——两类故障的可诊断性不同，排障时应先读文案。

## 四、给接口适配层的实现约束（据实测）

1. **不得以 HTTP 状态码判成败**——恒为 200；须解析报文体。
2. 成功路径：判 `errcode === 1`，业务数据取 **`Data`**，日志记录 **`traceId` 与 `resultMsg`**。
3. 异常路径：判 `code === -1`（业务 / 参数错误），异常信息取 `message`。
4. 鉴权失败路径：判 `__sys__.status === -1` 且 `msg` 含 `Full authentication is required` ⇒ 归类为**鉴权 / 签名问题**（非业务失败），并单独告警（该路径无 `traceId`）。
5. 请求体**严格按文档字段**，多余字段会被拒。
6. `p_password` 必须**小写 hex** 且**整串 URL 编码**；时间戳取**本机时间**、格式 `yyyyMMddHHmm`。
7. 回执解析需同时兼容上表**四种形状**（同一接口在不同场景会返回不同形状）。
8. **服务名写错可区分**：报错含"调用服务id[…]没有注册"⇒ 属服务名 / 路径问题，不是鉴权或业务问题。
9. **不得用 GET 探活**：GET 一律返回"服务器繁忙"，不反映服务是否存在（#11–#14）。
