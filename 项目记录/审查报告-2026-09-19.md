## 三、P1 缺陷（必须先修）

### P1-1 `?source=upper` 演示链路不可用（两层缺陷叠加）

| 项 | 内容 |
| --- | --- |
| 位置 | ① `src\services\api.js:156` + `src\services\mockUpperSource.js:43,109`；② `src\main.js:59-62` |
| 现象 | ①`MockUpperSource.next(prev)` 声明的契约是"传上一帧的 `inner`、返回 `{payload, inner}`"，`api.js` 却把整个返回值当 `prev` 回传 → **第 2 帧起 10 个数值字段全为 NaN**，被 `applyUpperPayload` 当"缺字段"丢弃（保留旧值）；②即使修好①，`main.js` 在 upper 模式仍每秒执行 `MockData.tick()`，**报文数据被模拟数据每秒覆盖** |
| 证据 | `contract-check` E 段 3 项 FAIL（第 2 帧 NaN：depth/speed/velocity_x/velocity_y/frameRate/gain/shutter/cameraDepth/progress/unitIndex；stage 跳成"完成"）；`browser-check` B2 项 FAIL（注入固定报文 depth=9.99，页面仍显示 mock 游走值 12.20） |
| 影响 | IF-D 联调演示路径不可用；`tests\README` 6.2「界面数值由报文提供」不成立；6.3 的"缺字段保留旧值"会假性通过 |
| 修法 | ①`const r = next(s); s = r.inner; const payload = r.payload;`；②upper 模式下停掉 mock tick（或适配层写入后立即渲染，避免被 tick 覆盖） |

### P1-2 失败补传（IF-B.9，P0 需求）只有实现、没有调用方

| 项 | 内容 |
| --- | --- |
| 位置 | `src\services\api.js:283`（`flushPending` 定义并导出）、`src\main.js:65-70`（上报定时器只调 `uploadReport`） |
| 现象 | MES 异常时失败报文只进内存队列（上限 5000，超出丢最早），**永不重发**；`CFG.mes.retry.max` 全仓无读取 |
| 证据 | 全仓 grep `flushPending` 仅命中定义与自检脚本；`tools\mock-mes\README.md:74-75` 承诺的"pendingCount 增长后回落""重启后补传不丢号"不成立 |
| 修法 | 上报定时器按 `baseDelayMs` 调用 `flushPending()`，并用 `retry.max` 约束重试次数；`getStatus().pendingCount` 接到设置页自检项 |
