## 二、工作包（每包 = 可派单、可验收）

> 验收判据一律写成"**断言级**"，且要求**行为判据**（不得源码字符串匹配；遵 D23 反静态防空洞）。

### W1 采集接入：IF-D 接收 + 采样落库
- **交付**：`server\http\`（最小路由）＋ `server\services\ingest.js`（IF-D 帧解析/校验/幂等/落库）＋ 配置位（`board.config.js` 的 `upper.*` 在服务端的读取）。
- **判据**：①脏帧被拒（字段缺失/时间非法/量纲不合法）且**不落库**；②同键重复帧**幂等或后到覆盖**（按 `DR-13` ＋ 负责人 2026-09-27 裁定的**帧级序号**扩展）；③**1 s 采样落库、500 ms 原始帧不落库**（需求既定）；④断连时**不阻塞**、状态可查（供 FR-2.6 断连 ≤5 s）。
- **依赖**：`measure`/`curve` 仓储（已有）；E31 的幂等键口径（我方侧可先用 `DR-13` 三字段，`uploadId` 仅回执核对）。
- **归属**：业务实现座位 ＋ 测试座位（断言）。

### W2 IF-A：接收 MES 派工/物料/工艺（本机提供接口）
- **交付**：`server\http\routes\ifA.js`（或等价）＋ `server\services\dispatch.js`（幂等写入 `device`/工单相关表）。
- **判据**：①**幂等**（同 `procOrderNo` 重复下发不产生重复工单）；②**访问控制**（未授权请求被拒，且拒绝原因是"鉴权"而非"参数"）；③**失败日志**（落 `op_log` 或专用表，可查询）；④形状与 `tools\mock-mes` 的 `/service/*`、`/dispatch` 对齐（**用于端到端**，真实契约待答复）。
- **依赖**：W6（进程入口）；`E16` 的 `op_log` 接线（顺带把"零调用方"消掉一半）。
- **归属**：业务实现 ＋ 测试。

### W3 判定引擎（我方判定，需求已定"判定由我方"）
- **交付**：`server\services\judge.js`（单任务五态：待测试/测试中/合格/不合格/待复检；判定对象＝深度/速度**标准上下限**）＋ 规则引擎（`FR-5.1～5.14`：4 类预警、**阈值可配**）。
- **判据**：①**闭边界语义**与前端一致（`FR-3.18` 临近带闭边界、压线不算超范围）；②**标准未设定（idle）**时不得误判（与前端同口径）；③预警分组/命名/等级色与 `C-88` 一致（**同态独立成条**，已由 R26-P2-2 收口）；④**与前端演示实现的对账**（同一输入序列，服务端判定 ≡ 前端判定，含跨零点班次与缺测）。
- **依赖**：`FR-3.13` 来源口径（`E27` 权威侧未定 ⇒ **本包只做服务端实现 + 对账断言**，不接线到界面）。
- **归属**：业务实现 ＋ 测试（**跨实现对账**断言放 `contract-check`）。

### W4 IF-B 上报 MES（13 字段 + 失败留存 + 人工重报）
- **交付**：服务端上报器（组装附录 2 十三字段、`uploadId` 生成复用 `platform\id.js` 真源）＋ **`E10` 单源化**（前端内存队列改为消费服务端 `upload_log`）＋ 人工重报入口的服务端状态接口（供 `UI-20` 消费）。
- **判据**：①**不做自动重试**（`V1.31/C-59`）：失败**落库留存**、有告警与**待补传条数**、**唯一人工入口**重报；②成功/失败/回执三态留痕；③`uploadId` 与 `platform\id.js` **同口径**（跨实现对账已有）；④**告警阈值走单一真源** `mes.queueWarnThreshold`（已落地）；⑤`E10` 的**双源消失**（浏览器队列不再是唯一真源）。
- **依赖**：W1（数据来源）、`E16`（`standard` 校验点）；地址/鉴权待答复 ⇒ 用 `mock-mes` 端到端。
- **归属**：业务实现 ＋ 测试 ＋ 独立复核（涉 `IF-B` 与 MES 交互，建议加一轮独立审查）。

### W5 SSE 推送 + 前端切真实源（保留演示降级）
- **交付**：服务端 SSE 端点（层间连接＝SSE，见技术栈）＋ 前端 `api.js` 增加"服务端模式"（配置开关），**保留** `mockData` 演示模式作为降级/培训用。
- **判据**：①SSE **断线重连**与"数据冻结/离线"降级（`FR-2.6` ≤5 s）；②前端在"服务端模式"下**不再自行造数**（同一时刻界面值与服务端一致，抽样比对）；③配置未就绪时**优雅回退**到演示模式（不黑屏、不抛未捕获异常——延续 E34/E38 的口径）；④**前端 `accumulateRun` ↔ 服务端 `stats.accumulateRunTime` 跨实现对账**（`E32` 收口）。
- **依赖**：W1/W3/W4；`E32`。
- **归属**：业务实现（前端）＋ 业务实现（服务端）＋ 测试。

### W6 进程入口与运行骨架
- **交付**：`server\index.js`（或等价）＝ HTTP 服务入口 ＋ 路由装配 ＋ 优雅退出 ＋ 健康检查（`/health`）＋ 日志（`op_log`/文件）＋ 配置装载（`board.config.js` 读服务端段）。
- **判据**：①**双进程开发模式**（后端服务 ＋ Edge kiosk，`ADR-0001 D1`）与**单进程交付模式**（`D2`）都能起；②端口/监听范围**默认仅本机/局域网**（不得对外，遵 `NFR-25`/`AC-09`）；③**崩溃可自愈**（未捕获异常不导致静默假活）；④启动自检（库可写、目录可写、时间源可读）。
- **归属**：业务实现 ＋ 测试（`harness-check` 已有"服务启停"夹具可扩）。

### W7 门禁与可观测扩展（横切，随各包推进）
- **交付**：新增/扩展测试（端点级端到端用 `mock-upper`/`mock-mes`；断言不依赖外网）、自检页（`FR-8.5`/`NFR-26`）数据源改为服务端真实探测、`tests\README.md` 权威区同步（由主代理单写）。
- **判据**：①新增端点的**正向 + 逆向**用例（脏数据/未授权/重复/断连）；②`E22` 的两项待补判据补齐（`3` 异常**正交/冻结**取证开关；`维保检修→0` 端到端上行夹具）；③**权威数字**随之上涨并四处同步。
- **归属**：测试座位 ＋ 主代理（README）。
