# P0-2 迁移方案：端点标识入去重键（`DR-13`／V1.45 第 11 处）

> 状态：**方案待批**（负责人点头后执行）｜日期：2026-10-19｜影响面：`measure_rt` 表结构 ＋ 去重口径 ＋ 若干门禁断言
> 依据：`需求文档\…V1.45.md` 第 11 处（`DR-13`：去重键**增列端点标识**；`seq` 现场不可得）｜`IF-D.8`（多 PLC／多端点）

---

## 一、要解决的问题

现状（`server\db\schema.sql:132`）：

```sql
CREATE UNIQUE INDEX ux_measure_rt ON measure_rt(equip_code, proc_order_no, collect_time);
```

**问题**：现场是**多端点**（5 台 PLC／18 个从站地址）。同一 `equipCode` 在同一秒从**两个端点**各来一帧 ⇒ 唯一键相同 ⇒ 后到的那帧被判 **`duplicate` 静默丢弃** ✗（数据丢一帧、且无告警）。

**目标**：去重键变为 **`equip_code + proc_order_no + endpoint + collect_time`** —— 同秒两端口各一行 ✓；同一端点的重复帧仍幂等 ✓。

## 二、方案（三步，事务内、可回滚）

| 步 | SQL | 说明 |
| --- | --- | --- |
| **A 加列** | `ALTER TABLE measure_rt ADD COLUMN endpoint TEXT;` | 非破坏；旧行为 `NULL` |
| **B 回填** | `UPDATE measure_rt SET endpoint = equip_code WHERE endpoint IS NULL;` | **为什么不留 NULL**：SQLite 唯一索引里 NULL **互不相等** ⇒ 留 NULL 会让"升级前的行"与"升级后的同帧"**判不成重复**（多插一行）。回填成 `equip_code` 与**新的回退链**（`endpointId → endpoint → unitId → equipCode`）一致 ⇒ 幂等 ✓ |
| **C 重建索引** | `DROP INDEX ux_measure_rt;`<br>`CREATE UNIQUE INDEX ux_measure_rt ON measure_rt(equip_code, proc_order_no, endpoint, collect_time);` | **必须重建**（只加列不改索引 ⇒ 去重口径没变 ✗）。**列序**选 `(equip_code, proc_order_no, endpoint, collect_time)`：既表达去重语义，又保住现有 `(equip_code, proc_order_no, …)` 前缀查询的索引可用性 ✓ |

**幂等**：三步都包在"检测旧形态才执行"里 ⇒ 重复执行无副作用（`PRAGMA table_info(measure_rt)` 查 `endpoint` 列是否存在；`PRAGMA index_info(ux_measure_rt)` 查索引列）。

**回滚**：`DROP INDEX ux_measure_rt; CREATE UNIQUE INDEX ux_measure_rt ON measure_rt(equip_code, proc_order_no, collect_time);`（`endpoint` 列**保留**、无害；回滚前须先把 `endpoint` 置 NULL 以免新索引不唯一 ⇒ 实际上回滚只在"新索引从未写入不同端点的行"时安全，故**建议回滚＝回退到升级前的数据库备份**）。
