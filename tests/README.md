# 测试与验证（tests/）

> 本项目为**无依赖的纯静态前端**，测试同样**零依赖**：只用 Node 内置模块，不引入 Jest/Vitest 等第三方测试框架、不使用 CDN（符合 `PROJECT_RULES` 第五章「不引入第三方库」与 NFR-25 内网隔离要求）。
> 本目录同时存放两类资产：**手工验证清单**（第一、二节）与**零依赖自检脚本**（第三节的脚本表；浏览器与长跑类脚本的权限要求与方法见第四、五节）。界面基准图目录 `screenshots-baseline/` 由**代码项目成员**维护。
>
> **脚本数量不在此处复述**（2026-09-20 修正）：此处原写"共 11 个"，是 2026-09-19 当天"11 个脚本"的实况，此后门禁持续增加（现为 `tests\*.js` **20 个**，其中带断言的离线门禁 **13 个**、需浏览器权限的 **3 个**）而此处未跟随 —— 这正是 `docs-cross-check` 第十节的立案症状"文档集体滞后"。**权威口径只有一处**：本节下方"已落地的自检脚本"表的行集合 ↔ `tests\run-all.js` 的 suite 清单，两者必须一致；数量随表走，写死数字必漂。

## 一、每次改动后必须做的验证（手工）

> 下面 1～5 项里可自动完成的部分已脚本化：第 1 项（控制台报错）、第 3 项（分辨率无滚动条）、第 4 项（特殊状态与参数）由 `tests/browser-check.js` 覆盖；第 2 项（逐页切换）也由它覆盖。方法与权限要求见第四节，剩余仍需人工判断的部分（配色观感、动效、截图比对）保留在本节。

### 1. 打开页面查报错

1. 双击根目录 `index.html`（或把 `index.html` 拖进浏览器）；
2. 按 `F12` 打开开发者工具，切到 **Console（控制台）** 标签；
3. 确认**没有红色报错**（黄色警告可忽略）；
4. 若出现红色报错，按报错里的文件名定位到 `src/` 下对应文件。

### 2. 逐个页面点一遍

依次点击底部 8 个标签，确认：

- 页面能正常切换，未出现空白页；
- 头部信息区（设备名、时钟、班次、人员）始终显示，不随切换消失；
- 底部状态区显示：版本、最后刷新时刻、上位机链路、MES 链路。

| 序号 | 页面 | 重点确认 |
| --- | --- | --- |
| 1 | 设备状态 | 运行模式与色带一致；航行器深度、航行速度有数值；两条任务曲线有图形或显示空态 |
| 2 | 任务数据 | 工单 8 项有值；深度/速度大号显示；进度条随秒推进；设备参数表有"正常/临近/超标"判定 |
| 3 | 班次信息 | 当前班次高亮；已进行/剩余时长随时间变化 |
| 4 | 生产统计 | 15 项统计有数值；合格率、稼动率在 0～100% 之间 |
| 5 | 设备异常 | 故障卡显示代码/类型/时间；预警 4 条；台账 5 行 |
| 6 | 维保台账 | 距下次维保天数与进度条一致；检修记录 4 行 |
| 7 | 公告备注 | 公告 5 条、工艺提示 5 条、待办 6 项 |
| 8 | 操作设置 | 默认锁定；输入 `8888` 后可录入与发布 |

### 3. 分辨率与缩放

在浏览器中把窗口调成以下尺寸，确认**没有横向滚动条、没有元素重叠**：

- 3840 × 2160（设计基准，75 寸电视 4K@30Hz）
- 1920 × 1080
- 1366 × 768

### 4. 特殊状态

| 操作 | 预期 |
| --- | --- |
| 键盘按 `D` | 运行模式转"故障锁定"、联网状态转红、底部弹出降级横幅；再按一次恢复 |
| 键盘按 `A` | 故障报警切换到下一条 |
| 地址栏加 `?curve=none` | 两条曲线显示空态提示"暂无已完成任务数据" |
| 地址栏加 `?link=off` | 以断连状态启动 |
| 地址栏加 `?unlock=1` | 以已解锁状态启动 |
| 地址栏加 `?tab=3` | 直接打开"生产统计"页 |

### 5. 数据与文案

- 中文无乱码；
- 数值格式统一：深度/速度 2 位小数、帧率整型、时间 `yyyy-MM-dd HH:mm:ss`；
- 修改需求后，界面文案与需求清单条款一致。

> **本节 1～5 项的自动化情况（2026-09-19 更新）**：
> ①红色报错、②逐页点击、④特殊状态（含键盘 `D`/`A`、`?curve`/`?link`/`?unlock`/`?tab`）→ `browser-check` 全覆盖；
> ③三分辨率"无滚动条" → `browser-check` 已覆盖；**"无元素重叠" → `overlap-check`（26 次页面加载，自动跳过父子与不可见元素）**；
> ⑤"无乱码" → `browser-check` 的编码与乱码特征断言已覆盖；"数值格式" → `ui-check` 的 UI-08；**"文案与需求一致" → `copy-check`（19 条映射、100+ 字符串已断言，另 3 条映射待确认）**。
> 仍属人工的：配色/动效的观感、75 寸实屏远距离可读性、UI-13 报警弹窗（未实现）。

### 6. 数据源与接口链路（2026-09-18 新增）

| 序号 | 验证项 | 操作 | 期望结果 |
| --- | --- | --- | --- |
| 6.1 | 默认数据源 | 打开 `index.html` | 各页有数据，页脚右侧"上位机链路/MES 链路"显示正常 |
| 6.2 | 上位机报文数据源 | 地址栏加 `?source=upper` | 界面正常显示，深度/速度/帧率等由报文提供（走适配层，与真实链路一致） |
| 6.3 | 报文缺字段容错 | 临时把 `mockUpperSource.js` 某个字段删掉 | 该项**保持上一次数值不清零**，其余正常；控制台提示缺失字段 |
| 6.4 | 数据冻结判定 | 在 `board.config.js` 把 `upper.staleMs` 改小（如 500），再减速推送 | 超时后判定"数据已冻结" |
| 6.5 | 配置生效 | 改 `board.config.js` 的 `shift.list` 或 `production.planQty` | 界面班次/计划数随之变化，无需改代码 |
| 6.6 | 字段映射生效 | 改 `fieldMap.js` 某条映射的 `key` | 对应字段取值随之变化（证明字段名可配置） |
| 6.7 | 模拟上位机 | `node tools/mock-upper/mock-upper.js --once` | 打印一帧符合契约的报文，字段与 `fieldMap` 键一致 |
| 6.8 | 上报与回执（status 风格） | 起 `mock-mes --receipt status`，看板配置 `mes.baseUrl` | `GET /log` 收到周期上报，13 个字段齐全，回执判定成功 |
| 6.9 | 上报与回执（code 风格） | 起 `mock-mes --receipt code` | 回执判定同样成功（两种风格都兼容） |
| 6.10 | 失败补传 | 起 `mock-mes --fail-rate 0.5` | 失败报文进入待补传队列（**不自动重发**：`flushPending` 只刷新状态与告警、人工 `retryPending` 才发送；本地持久化留存），`/log` 无丢号 |
| 6.11 | 派工下发（IF-A） | `mock-mes --board <看板地址>` 后 `POST /dispatch` | 看板收到派工信息 |

> 6.8～6.11 需要看板服务端提供接收端点；当前纯静态 Demo 下可先只验证 **6.1～6.7**。

## 四、浏览器验证怎么做（无头 Edge + CDP）

`tests/browser-check.js` 不引入任何 npm 依赖，用本机已安装的 **Microsoft Edge** 无头模式 + **Chrome DevTools Protocol** 驱动真实页面：

| 环节 | 做法 |
| --- | --- |
| 启动浏览器 | `msedge --headless=new --disable-gpu --remote-debugging-port=18920 --user-data-dir=<临时目录> about:blank`，路径自动探测 `C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe`，可用环境变量 `MSEDGE_PATH` 覆盖 |
| 连接协议 | 从 `http://127.0.0.1:18920/json/list` 取页面 target 的 WebSocket 地址，用 **Node ≥22 内置的全局 `WebSocket`** 直连 CDP，自带极简客户端（`send/on`），不装 `puppeteer`/`playwright` |
| 断言方式 | `Runtime.evaluate` 在页面里取真实 DOM/计算样式（如 `getComputedStyle`、`scrollWidth`、`classList`），再用本脚本的 `check()` 判定 |
| 报错采集 | 同时开 `Runtime.enable` / `Log.enable`，把 `console.error`、未捕获异常、浏览器 error 日志收进 `consoleErrors`，对应"控制台无红色报错" |
| 页面截图 | 用 Edge 命令行 `--screenshot=<png> --window-size=3840,2160`（CDP 的 `captureScreenshot` 在 4K 下会挂住，已改为命令行并加 60 秒超时）；产物落在 **`tests/._verify/`**，该目录已被 `.gitignore` 忽略，不会进版本管理 |
| 环境变量 | `MSEDGE_PATH` 指定浏览器可执行文件；`DSH_EDGE_PORT` 指定调试端口（默认 18920） |

**权限要求（重要）：** Chromium 启动时必须创建 mojo 命名管道，受限沙箱（dsh 的 `workspace-write`）会以
`FATAL:mojo/platform_channel.cc: Check failed: 拒绝访问 (0x5)` 直接启动失败。因此本脚本要在**可创建命名管道的权限下**运行：

- 在 dsh 会话里：让助手以 `danger-full-access` 运行该命令（会弹一次批准）；
- 或在普通 PowerShell / 计划任务里直接 `node tests\browser-check.js`。

脚本在起不来时会整体记 `[SKIP]` 并退出码 0，不会误报成缺陷。

**新增一个浏览器场景**只需三步（参考 B2 段）：`await openPage('?参数')` → `await evaluate('页面内表达式')` → `check('断言名', 条件, '实测值')`。

**本脚本不覆盖**（仍需人工或后续补充）：动效/闪烁等主观项（UI-09/UI-18）、报警弹窗（UI-13，Demo 已声明未实现）、长时间稳定性与内存（见第五节）、截图与最新界面的逐像素比对（见 `tests/screenshots-baseline/README.md`）。

## 五、长时间运行（整班次 / 7×24）怎么做

`tests/stress-check.js` 用与第四节同一套无头 Edge + CDP 工具链，把看板连续挂 8 小时（默认，覆盖一个整班次），
每 10 分钟采样一次、每小时轮巡 8 个页面并切两次断连。跑之前请按 5.1 逐条确认。

### 5.1 跑之前必须确认的（2026-09-19 在本机实测的结论，换机器要重查）

| 检查项 | 命令 | 本机实测 | 要求 |
| --- | --- | --- | --- |
| 系统睡眠 | `powercfg /q SCHEME_CURRENT SUB_SLEEP STANDBYIDLE` | AC/DC = **0（永不）** | 必须为 0；否则整段长跑会被挂起 |
| 休眠 | `powercfg /q SCHEME_CURRENT SUB_SLEEP HIBERNATEIDLE` | AC/DC = **0（永不）** | 同上 |
| 无人参与睡眠（隐藏项） | `powercfg /q SCHEME_CURRENT 238c9fa8-0aad-41ed-83f4-97be242c8f20 7bc4a2f9-d8fc-4469-b07b-33eb785aaca0` | 未配置 | 主睡眠为 0 时无影响 |
| 关闭显示器 | `powercfg /q SCHEME_CURRENT SUB_VIDEO VIDEOIDLE` | AC 900 s | 无影响（无头浏览器不需要屏幕，不终止进程） |
| 关闭硬盘 | `powercfg /q SCHEME_CURRENT SUB_DISK DISKIDLE` | AC 1200 s | 无影响（磁盘可唤醒） |
| 电池（是否笔记本） | `Get-CimInstance Win32_Battery` | 无（台式机） | 笔记本必须同时确认 DC 值 |
| 关机/重启/睡眠计划任务 | `Get-ScheduledTask` 过滤 `shutdown` / `/r` / `SetSuspendState` | 无 | 必须无 |
| Windows Update 待重启 | `Test-Path 'HKLM:\SOFTWARE\Microsoft\Windows\CurrentVersion\WindowsUpdate\Auto Update\RebootRequired'`；`Get-Service wuauserv` | False；已停止（手动） | 无待重启标记、避免自动重启 |
| 磁盘空间 | `[System.IO.DriveInfo]::GetDrives()` | C 117 GB / D 247 GB 可用 | 留几十 MB 即可（只写 CSV/日志/少量截图） |

> `powercfg /req`（查看当前有无程序阻止睡眠）**需要管理员权限**；主睡眠已为 0 时不必查。

### 5.2 跑的时候不能做的事

- **不要注销账号**：长跑进程挂在当前登录会话下，注销会终止整棵进程树。**锁屏不影响**——脚本启动 Edge 时带了
  `--disable-background-timer-throttling`、`--disable-renderer-backgrounding`、`--disable-backgrounding-occluded-windows`，
  锁屏/遮挡都不会让页面定时器被降频。
- 不要手动关机/重启（含"更新并重启"），也不要在跑的过程中改电源计划。

### 5.3 结果怎么读，以及它和验收指标的关系

- 明细与结论：`tests/._verify/stress-<时间戳>.csv`（每 10 分钟一行）、`stress-<时间戳>.log`（进度，可随时 tail）、
  `stress-<时间戳>-summary.json`（7 项判据汇总）、`-start.png` / `-end.png`（首末截图）。任一项判据失败即退出码 1。
- 7 项判据：采样成功率、时钟持续推进、标签按钮恒为 8、激活面板恒为 1、无未捕获异常与 `console.error`、
  堆增长（≤2 倍且 <100 MB）、DOM 增长（≤50%）。
- **8 小时 ≠ 验收要求**：NFR-05 要求 **≥72 小时内存压力测试**（常驻 ≤1.2 GB、峰值 ≤1.8 GB），NFR-06 要求
  **连续 30 天**无泄漏/无卡顿/无重启；这两条必须在**目标硬件**上按**系统级口径**（整机内存/CPU，而非进程工作集）复测。
  本脚本只做开发期的"整班次筛查"。
- 2026-09-19 首轮 8 小时实测观察（供参考，非结论）：页面 **JS 堆 9.5 MB 零增长、DOM 690 节点零漂移、零红色报错**；
  但浏览器进程组的**工作集合计约 2 GB**（21 个进程，含共享页重复计数，不等于整机占用）——这是 NFR-05 的**风险提示**，
  需要在目标机上用系统级口径复核。
