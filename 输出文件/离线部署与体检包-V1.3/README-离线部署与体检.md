## 2. 装 Node —— **本包已自带，零操作**（不改 PATH、不需要管理员）

本包内**已经解压好**便携 Node（`._node\node.exe`，v24.21.0，与开发机同版本）。**你什么都不用装、也不用改环境变量**：双击 `体检-双击运行.cmd` 时，入口会**自动找到**同目录的便携 Node，并**只在本次运行内**把它前置到 PATH（屏幕会打印 `Node : …\node.exe   portable, session-only PATH`）—— **不改系统、不改用户环境变量、不需要管理员**。

> 为什么做成"自动找"：Win10 与 Win11 的图形入口**不一样** —— Win11 的「设置 → 系统」里**没有**"系统信息"这一项，高级系统设置藏在「**关于**」里（2026-09-28 在本机 Win11 上实测踩到）。故本包**不再要求任何 GUI 操作**。

**可选**（只在你想让本机其它程序也能用 Node 时才做）：

1. **临时（仅当前窗口，最安全）**：`set PATH=<本包路径>\._node;%PATH%`
2. **永久（图形）**：Win11 = `设置 → 系统 → 关于 → 高级系统设置 → 环境变量`；Win10 = `设置 → 系统 → 关于（旧版称"系统信息"）→ 高级系统设置 → 环境变量`；再在「系统变量」里选 `Path` → 新建 → 填 `<本包路径>\._node`（或你自己的 Node 目录）
3. **永久（命令行，用户作用域，适合批量装机）**：`[Environment]::SetEnvironmentVariable('Path', [Environment]::GetEnvironmentVariable('Path','User') + ';<本包路径>\._node', 'User')`
   ⚠ **不要用 `setx PATH "%PATH%;…"`**：`setx` 会把"系统 PATH ＋ 用户 PATH"合并后写回**用户变量**，且**超过 1024 字符会被静默截断** —— 一次就可能把 PATH 弄坏（只能靠备份或还原点恢复）。

（若走"推荐做法"，**无需任何验证**：直接双击 `体检-双击运行.cmd`，报告会打印 Node 的实际路径与版本。）

> 为什么要 Node 24：`node:sqlite` 在 Node 22.5+ 仍属实验性、需 `--experimental-sqlite`；**Node 24 起免标志**（ADR-0002 D10）。

## 3. 体检（双击即可）

双击 `体检-双击运行.cmd`（或 `powershell -NoProfile -ExecutionPolicy Bypass -File 部署环境体检.ps1`）。
脚本会**只读**采集并生成 `._env-report\部署环境体检报告-<主机名>-<时间戳>.txt`，内容分六节：

1. **操作系统与固件** —— Windows 版本/内部版本号、区域与时区、BIOS、整机型号、PowerShell 版本（`Q-26`）
2. **CPU / 内存 / 存储** —— **兆芯 CPU 型号与核数**、内存条与总量、磁盘与分区余量（`Q-26`、`NFR-05` 前置）
3. **显示与缩放** —— 显卡与驱动版本、**当前分辨率与刷新率**、显示器 EDID 名称、DPI 缩放（`ENV-01` 目标 **3840×2160**、`ENV-16`）
4. **无人值守策略** —— 睡眠/休眠/关屏（AC/DC 索引）、无线省电、屏保、**更新自动重启策略**、待重启标志（`DEP-04`）
5. **运行时与浏览器** —— **`node` 实际路径**（本包自带时即包内路径）、`node --version`、**`node:sqlite` 冒烟**（真建表读写）、`msedge.exe` 路径与版本、网卡与 IP（离线也应看到"未连接/无地址"）、`w32time` 状态
6. **仓库与门禁** —— 若仓库已就位且 Node ≥ 24，自动跑 `node tests\preflight.js` 与 `node tests\run-all.js --fast` 并把输出一并写进报告

> **目标机若未安装 git**：第六节会出现 `docs-check` 红项（读不到提交历史 ⇒ 打印"共 0 条"）与 `docs-cross-check` 红项（逐脚本比对不成立）—— **环境所致、不是代码问题**，其余读数与红项判读不受影响，照常回传即可。报告第六节也会自动打印一行 `git 可用性` 说明这一点。

> **第六节的门禁输出怎么读**：`--fast` 会跳过浏览器类与长跑脚本，故权威对账会打印"**未执行**：本轮未跑全离线门禁（缺 N 个：…）" —— 这是**子集对全量的正常提示**（技术债 **E50** 已修：旧版在此处会误报"权威数字已漂移"）。真正要看的是各脚本的 `通过 / 失败` 计数与红项。

> **另有一项独立的库结构核查（双击 `体检-库结构核查.cmd`）**：体检脚本查机器，**它查数据库文件**。看板库里有一批结构是"后来加给既有表"的（**列面 6 列**：`op_log.team_code`、`measure_rt.unit_index`、`upload_log.fail_reason`／`updated_at`、`shift_stat.run_sec_day1`／`run_sec_day2`；**索引面 2 个**：`ix_op_log_team`、`ix_measure_rt_collect_time`），若缺，服务跑起来**读数全绿**（版本/指纹/自检都正常）却**一写入就报错**（缺索引则是**慢** —— 按时间范围取数走全表扫，**不影响正确性**） —— 属"开发机全绿、现场老库才炸"的形态（技术债 `E71`／`E73`）。**缺列 ≠ 数据丢失**：用修复后的构建**启动一次服务**即自动补上（既有行零回填），随后**复查必须为"缺列 0"**。判读表与闭环三步见 `体检-库结构核查-执行方法.md`。
