## 二、实测到的四种回执形状

| 场景 | 回执形状 | 关键字段 |
| --- | --- | --- |
| **成功** | `{errcode, __sys__{msg,traceId,detailMsg,msgKey,status}, __version__, Data, resultMsg, __blocks__}` | `errcode = 1`；`__sys__.status = 0`；`Data` 为**数组**；`resultMsg` 为中文结果描述；`traceId` **有值** |
| **业务 / 参数异常** | `{code, message, data, __sys__{msg,status}}` | `code = -1`；`message` 为提示；`data = null`；**无 `traceId`** |
| **未通过鉴权**（含签名错误） | `{__sys__{msg,traceId,detailMsg,msgKey,status}, __version__, __blocks__}` | `__sys__.status = -1`；`msg` 为英文提示；`traceId` 为**空串** |
| **服务未注册** | `{__sys__{msg,…,status:-1}, __version__, errorMsg, __blocks__}` | `msg` / `errorMsg` 为中文："调用服务id[X]没有注册，无法执行服务调用！" |

> **四种场景的 HTTP 状态码均为 200**，成败只能由**报文体**判断。

## 三、我方结论（供贵方核对）

1. **签名链路可用**：我方以 Node.js 零依赖实现的等价签名被贵方平台接受，查询接口调用成功。
2. **回执结构**：实际存在上表**四种形状**，与接口定义附件 §1.3 所写 `{ "status": 1, "msg": "…", "data": {} }` **均不完全一致**；其中"业务 / 参数异常"形状与贵方回签件批注的"`code`、`msg`"一致。
3. **`S_ME_BD_0003`（人员资质）实为查询接口**：仅发送 `workshopNo` 即返回人员列表；按接口定义所写的"上报"入参发送反而返回异常。
4. **`S_ME_BD_0001` / `S_ME_BD_0002` 方向无误**：我方调用、返回台账数据；请求参数栏中的 `status` / `msg` 属回执字段，实测证明请求**只需 `workshopNo`**。
5. **`workshopNo = "19"` 为有效编码**（由人员资质接口返回数据证实）；`Data` 返回空数组应系测试环境**暂无班组与设备数据**。
6. **地址书写**：单斜杠与双斜杠均可调用，`…:18000//fxzg-be/...` 属书写瑕疵，不影响联调。
7. **鉴权错误不可细分**：签名错误与未携带签名返回**同一提示**（`traceId` 为空），排障时建议保留 `traceId`；而"服务未注册"有**专门文案**，可明确区分。
8. **入参严格校验**：多余字段会触发异常，我方将严格按接口定义字段发送。
