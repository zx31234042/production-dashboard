## 一、定位与总体约定

**`IF-A` 的四个接口由我方（看板）提供、由 MES 调用**（对应贵方接口定义 §1.1.1–§1.1.4）。

| 项 | 约定 |
| --- | --- |
| 传输 | **HTTP(S) POST**，`Content-Type: application/json; charset=utf-8` |
| **响应** | **`{"errcode": 1 / -1, "resultMsg": "…"}`**（按贵方 2026-10-23 答复：以文档定义的 `errcode`/`resultMsg` 为准） |
| 幂等 | 每个接口按**业务键**幂等（见各接口"幂等键"）；**重复报送不产生重复业务行**，仍回 `errcode=1` |
| 时间 | 统一字符串 `YYYY-MM-DD HH:mm:ss`（**北京时间**） |
| 失败 | 校验失败回 `errcode=-1` ＋ `resultMsg` 说明；**每次调用留痕**（时间/来源/报文摘要/结果），可追溯 |
| 鉴权 | **待定**（见 §四）：当前预留 `Authorization` 头；正式方案请贵方指定（Token／签名／IP 白名单） |

**基地址（待现场确认）**：`http://{看板主机}:{端口}` —— 端口与是否经专线/网关请贵方与现场确认。

## 二、四个接口

### `IF-A.1` 派工信息下发

- **路径（建议）**：`POST /if-a/dispatch`
- **幂等键**：`techNoticeNo + procOrderNo`（同一派工单重复报送视为更新）
- **请求字段**（按贵方 §1.1.1）：
  `techNoticeNo`／`batchNo`／`procOrderNo`／`productCode`／`drawingNo`／`productName`／`heatBatchNo`／`parentPartNo`／`processNo`／`processName`／`unit`／`dispatchQty`／`processRoute`／`processNum`／`planStartTime`／`planEndTime`（其余字段按贵方文档）
- **我方用途**：落 `task` 表（**`planStartTime`/`planEndTime` 是我方"当前工单"判定的时间窗**）。

### `IF-A.2` 物料信息下发

- **路径（建议）**：`POST /if-a/material`
- **幂等键**：`techNoticeNo + procOrderNo + materialCode`
- **请求字段**：`techNoticeNo`／`batchNo`／`procOrderNo`／`processNo`／`processName`／`materialCode`／`materialName`／`materialType`／`materialBatch`／`specModel`／`materialDesc`／`qty`／`unit`

### `IF-A.3` 工艺信息下发

- **路径（建议）**：`POST /if-a/process`
- **幂等键**：`procOrderNo`（＋`processNo`）
- **请求字段**：`procOrderNo`／`productCode`／`drawingNo`／`productName`／`processNo`／`processName`／`processRoute`／`bomInstance`／`workInstruction`

### `IF-A.4` 设备运行信息

- **路径（建议）**：`POST /if-a/equipment`
- **幂等键**：`procOrderNo + equipCode + timestamp`
- **请求字段**（按贵方 §1.1.4）：`procOrderNo`／`productCode`／`drawingNo`／`processNo`／`processName`／`equipCode`／`equipName`／`timestamp`／`equipStatus`
- ⚠ **须贵方澄清一处**：贵方 2026-10-23 答复"`1.1.4` 应该是 **MES 调我方**，上报信息用于 **MES 方确认设备状态**"。按 §1.1.4 的字段（含 `equipStatus`），它读起来是"**贵方把设备运行信息推给我方**"；但"用于 MES 确认设备状态"又像"**贵方向我方查询状态**"。
  ⇒ 请确认属哪一种：
  1. **贵方推送**设备运行信息给我方（本接口如上报文）；或
  2. **贵方查询**：我方提供一个**查询接口**（`GET /if-a/equipment/status?equipCode=…`）返回我方当前状态；
  3. 或**两者都要**。

### `IF-A.5` 横切要求（我方承诺）

- **幂等**：见上表各接口的幂等键；重复调用回 `errcode=1`，不产生重复行；
- **访问控制**：鉴权待定；未授权一律 `errcode=-1`（不泄露字段级信息）；
- **失败日志**：每次调用留痕（时间/来源 IP/报文摘要/结果/`resultMsg`），保留期与查询方式待定。

## 三、响应示例

```json
// 成功
{ "errcode": 1, "resultMsg": "成功" }

// 业务失败（示例：时间窗非法）
{ "errcode": -1, "resultMsg": "planEndTime 早于 planStartTime" }
```

## 四、请贵方确认（5 项）

1. **鉴权方式**：Token／签名／IP 白名单？（我方预留 `Authorization` 头）
2. **基地址与端口**：我方主机以哪个地址端口对外（是否经网关）？
3. **`IF-A.4` 的形态**：推送／查询／两者（见 §二 `IF-A.4` 的三种选项）。
4. **字段最终版**：§二 的字段取自贵方 §1.1.x，若贵方已有**更新版字段表**，请以更新版为准发我。
5. **调用频率与超时**：贵方计划的下发频率、期望响应时限（我方默认 5 s 内返回）。

## 五、内部备注（**不要发出**）

- `IF-A.4` 的"推送 or 查询"是**真歧义**，必须在发信时点明 —— 若按"查询"实现，我方要新增一个 `GET` 路由（小改动）；若按"推送"，则复用现有 `POST` 落库路径。
- 本草案**没有**承诺字段级校验细节（各字段长度/枚举），等贵方给**字段表最终版**再细化；**不臆造枚举值**。
- 鉴权未定前，接口**不对外暴露**（现场联调前由负责人决定是否临时 IP 白名单）。
