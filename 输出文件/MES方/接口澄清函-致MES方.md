## 一、背景说明

按甲方澄清，**MES 通讯由 MES 服务器与看板主机（本机）直接进行，不经过相机系统上位机**。因此本项目需实现两个方向的接口：

| 方向 | 接口归属 | 说明 |
| --- | --- | --- |
| **MES → 本机** | **我方提供接口**，贵方调用 | 派工、物料、工艺、设备运行信息下发 |
| **本机 → MES** | **贵方提供接口**，我方调用 | 报工、异常、关键运行参数、OEE 等上报 |

**关于数据上传字段：** 甲方来源文件中的**附录 2《MES数据上传接口规范》由设备 PC 上位机方编制**，本函不对其字段内容提出确认要求；为便于贵方了解上报数据的范围与格式，**附录 2 完整文本附于本文档最后**，相关字段疑问请与上位机方核对。

本函仅就**贵方接口定义本身**需要澄清的事项提出，共 6 项。

## 三、接口清单确认

### 3.1 我方提供接口（MES → 本机）

| 序号 | 接口名称 | 我方理解的关键字段 |
| --- | --- | --- |
| A-1 | 派工信息下发 | `techNoticeNo`、`batchNo`、`procOrderNo`、`productCode`、`drawingNo`、`productName`、`heatBatchNo`、`processNo/Name`、`dispatchQty`、`processRoute`、`planStartTime/EndTime`、`dispatchTarget` |
| A-2 | 物料信息下发 | `materialCode/Name/Type/Batch`、`specModel`、`qty`、`unit` |
| A-3 | 工艺信息下发 | `processRoute`、`bomInstance`、`workInstruction`（作业指导书下载路径） |
| A-4 | 设备运行信息 | `equipCode`、`equipName`、`timestamp`、`equipStatus` |

**请确认：** 以上 4 个接口的**实际服务名与方法名**，以及 MES 的**调用时机与频率**（例如派工是实时推送还是定时下发）。

### 3.2 我方需调用接口（本机 → MES）

| 序号 | 接口名称（接口编码） | 我方调用时机 |
| --- | --- | --- |
| B-1 | 报工信息接收（`REPORT_INFO_RECV`，见 M-2） | 单件测试完成时 |
| B-2 | 物料消耗信息接收 | 按班次或事件触发 |
| B-3 | 生产异常信息接收（`ABNORMAL_INFO_RECV`） | 设备故障与异常闭环时 |
| B-4 | 设备能耗信息接收（`EQUIP_ENERGY_RECV`） | 按班次统计 |
| B-5 | 关键运行参数接收（`PARAM_INFO_RECV`） | 周期上报（建议 1 s） |
| B-6 | OEE结果接收（`OEE_RESULT_RECV`） | 班次结束时 |
| B-7 | 人员班组资质（`STAFF_QUALIFICATION_RECV`） | 按需/定时 |

**请确认：** 上述接口是否即为本项目实际需要调用的全部接口；有无需要增减。

## 附录：甲方《信息化看板显示内容》附录 2 全文

> **来源说明：** 本附录取自甲方来源文件《信息化看板显示内容》，**由设备 PC 上位机方编制**，看板系统与 MES 系统均按此规范执行。此处全文附上，仅供贵方了解上报数据的范围与格式；**如对字段含义、取值或格式有疑问，请与上位机方核对**（该部分内容的确认责任在上位机方）。

### 1. 接口基础要求

- 接口地址、端口、请求头由 MES 方提供，联调阶段完成确认；
- 传输方式：内网 HTTP POST；备用传输方案 WebService；
- 数据格式：标准 JSON；
- 唯一校验字段：设备编号（必填）；
- 数据推送方式：周期定时上传，测试运行过程持续推送实时瞬时工艺数据。

### 2. 上传报文字段说明（共 13 项）

| 参数名称 | 字段标识 | 数据来源 | 数据类型 | 说明 |
| --- | --- | --- | --- | --- |
| 设备编号 | `equipCode` | MES 工单 | 字符串 | 唯一匹配标识，必填 |
| 生产任务编号 | `procOrderNo` | MES 工单 | 字符串 | 本次水下测试工单编号 |
| 实时帧率 | `frameRate` | PC上位机 | 整型 | 高速相机当前实际帧率 |
| 相机增益 | `gain` | PC上位机 | 浮点型 | 相机实时增益参数 |
| 快门速度 | `shutter` | PC上位机 | 整型 | 相机当前快门参数 |
| 相机水下深度 | `cameraDepth` | PC上位机 | 浮点型 | 现场传感器采集深度数值 |
| 实测水下深度 | `depth` | PC上位机 | 浮点型 | 航行器水下深度 |
| 实测航行速度 | `speed` | PC上位机 | 浮点型 | 航行器 X-Y 平面合成速度 |
| 实测水平速度 | `velocity_x` | PC上位机 | 浮点型 | 航行器 X 方向分速度 |
| 实测垂直速度 | `velocity_y` | PC上位机 | 浮点型 | 航行器 Y 方向分速度 |
| 采集时间 | `collectTime` | Java 程序 | 字符串 | 时间格式 `yyyy-MM-dd HH:mm:ss` |
| 设备运行状态 | `testStatus` | PC上位机 | 整型 | 0=待机 1=测试中 2=测试完成 3=设备异常 |
| 上传流水号 | `uploadId` | Java 程序生成 | 字符串 | 用于 MES 数据去重、回执核对 |

### 3. 报文示例

**请求报文：**

```json
{
  "equipCode": "SX-UNDERWATER-001",
  "procOrderNo": "MES20260728001",
  "frameRate": 400,
  "gain": 2.5,
  "shutter": 500,
  "cameraDepth": 12.00,
  "depth": 12.68,
  "speed": 5.0,
  "velocity_x": 4.9,
  "velocity_y": 0.1,
  "collectTime": "2026-07-28 15:30:22",
  "testStatus": 1,
  "uploadId": "UP20260728153022001"
}
```

**成功返回回执：**

```json
{ "code": 200, "msg": "数据接收成功", "uploadId": "UP20260728153022001" }
```

**异常返回回执：**

```json
{ "code": 5001, "msg": "设备编号不存在/关键字段缺失", "uploadId": "UP20260728153022001" }
```
