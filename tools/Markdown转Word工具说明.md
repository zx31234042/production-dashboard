# Markdown 转 Word 工具说明

| 项目 | 内容 |
| --- | --- |
| 文档名称 | Markdown 转 Word 工具说明 |
| 版本 | v1.4（E14 占用处置 ＋ E15 入口 BOM 自检 ＋ E106 失败路径安全写） |
| 编制日期 | 2026-09-18 |
| 存放位置 | `tools\` |
| 用途 | 把项目中的 Markdown 文档（需求清单、说明文档等）转换为可直接流转的 Word（.docx）文件 |

---

## 一、工具清单

| 文件 | 说明 |
| --- | --- |
| `tools\md2docx.ps1` | **基础版**：Markdown → Word，支持标题、正文、表格、列表、引用、代码块、分隔线 |
| `tools\md2docx-img.ps1` | **增强版（本次新增）**：在基础版之上支持**图片嵌入**，并自动压缩截图、自动生成图注 |

> 两个脚本相互独立，按需选用：纯文字文档用基础版，含界面截图的文档用增强版。

---

## 二、运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10/11 或 Windows Server |
| 运行环境 | PowerShell 5.1（系统自带，无需额外安装） |
| 第三方依赖 | **无**。不需要 Python、Node.js、Pandoc 等，也不依赖外网 |
| 使用到的内置组件 | .NET 程序集 System.IO.Compression（打包 docx）、System.Drawing（图片缩放） |

## 三、使用方法

在项目根目录执行（示例为生成甲方用的界面说明文档）：

```powershell
& ".\tools\md2docx-img.ps1" -InPath ".\输出文件\甲方\水池高速摄像生产管理看板-前端界面Demo说明.md" -OutPath ".\输出文件\甲方\水池高速摄像生产管理看板-前端界面Demo说明.docx" -DocTitle "水池高速摄像生产管理看板系统 前端界面 Demo 说明"
```

### 参数说明

| 参数 | 必填 | 默认值 | 说明 |
| --- | --- | --- | --- |
| `-InPath` | 是 | — | 输入 Markdown 文件路径，按 UTF-8 读取 |
| `-OutPath` | 是 | — | 输出 .docx 路径；目录不存在时自动创建 |
| `-DocTitle` | 否 | Document | 写入 Word 文档属性的标题 |
| `-MaxImageWidth` | 否 | 1920 | 图片宽度超过该像素值时等比缩小 |
| `-JpegQuality` | 否 | 85 | 缩放后另存为 JPEG 的质量（1–100） |

## 四、支持的 Markdown 语法

| 语法 | 转换结果 |
| --- | --- |
| `#` ～ `####` | 一～四级标题，带 Word 大纲级别（可在 Word 中自动生成目录） |
| 普通段落 | 正文段落 |

| `` `代码` `` | 行内等宽红字 |
| `<br>` / `<br/>` / `<br />` | **段落内换行（本次新增）**：转成 Word 的行内换行，**不拆成多个段落**，主要用于表格单元格内的多行分段 |
| `-` / `1.` | 项目符号列表、编号列表（支持一级缩进） |
| `>` | 引用块（左侧灰色竖线，灰色斜体） |
| 三个反引号代码块 | 灰底等宽代码块 |
| `---` | 分隔线 |
| 表格 | 三线表样式，首行加粗并带浅蓝底色，跨页自动重复表头 |
| `![说明](图片路径)` | **插入图片（本次新增）**，按正文宽度居中，图下自动附加灰色居中图注 |

## 五、图片处理规则（本次新增功能）

| 规则 | 说明 |
| --- | --- |
| 路径解析 | 可为绝对路径；推荐使用**相对于 Markdown 文件所在目录**的相对路径（如 `..\..\src\assets\screenshots\xxx.png`），便于文档与图片整体搬迁 |
| 自动压缩 | 宽度超过 `-MaxImageWidth` 时**等比缩小并转为 JPEG**，显著减小文档体积 |
| 原样嵌入 | 未超宽的图片按原格式、原尺寸嵌入 |
| 宽度控制 | 在图片语法后加 `{w=60}`，表示按正文宽度的 60% 显示（默认 100%） |
| 缺失容错 | 图片路径不存在时，在文档中输出占位提示文字，转换过程不中断 |
| 图注 | 方括号内的说明文字自动转为图片下方的居中灰色小字图注 |

**使用示例**

```
![图 1　设备状态页](..\..\src\assets\screenshots\01-设备状态-任务曲线.png)
![图 2　设备参数局部放大](..\img\zoom.png){w=60}
```

**实测压缩效果**：本次《前端界面 Demo 说明》中的 10 张 3840×2160 界面截图，由原图约 7.5 MB 压缩至 **1.6 MB**，文档共 10 张插图，Word 打开正常、文字清晰。

## 七、重要注意事项

1. **脚本必须以「UTF-8 带 BOM」保存。**
   PowerShell 5.1 在脚本没有 BOM 时会按系统 ANSI 编码解析，脚本内的中文（例如字体名「微软雅黑」）会变成乱码并被写入 docx，导致 Word 中文字体回退。
   本次已为两个脚本补齐 BOM；若后续用其他编辑器修改脚本，请确认保存为 **UTF-8 with BOM**。
   > **改完必须复查 BOM**：具体的复查命令、以及"改坏会怎样"的完整说明见 **第十节（十）**（`E15`）；这条不是建议，是**门禁**（`tests\files-check.js` 会红）。
2. 输入 Markdown 文件按 **UTF-8** 读取，有无 BOM 均可。
3. 输出的 .docx 为标准 OOXML 包，可直接用 Microsoft Word 或 WPS 打开，无需转换。
4. 转换过程会在输出目录临时创建 `._docx_build` 工作目录，完成后自动删除，不会残留。
   > **E106 起**：新件先写成该目录里的 `_md2docx_pkg.new` **临时件**，**只有新件完整生成并通过自检之后**，才用**一次原子替换/改名**落到目标。脚本抛错、目标被占用、`Ctrl-C` 都会把构建目录与临时件清掉；只有"进程被强杀"这类最狠的中断才可能残留，而**下一次运行入口会先清掉它**。详见 **第十二节**。
5. **目标 .docx 被 Word/WPS 打开时**：脚本会先在**转换前**探测目标是否被占用，给出「请先关闭 `<文件名>`（可能被 Word/WPS 打开）」并退出，**不会**抛 IO 异常、也不会留下 `._docx_build` 或 `~$*` 锁文件。详见 **第十一节（十一）**（`E14`）。
6. **失败不会毁掉旧件（E106）**：任何失败路径上，已存在的旧 `.docx` **一个字节都不会被改**——工具从不"先删旧件再写新件"。见 **第十二节**。

## 十、脚本自身的 UTF-8 BOM 自检（E15）

### 10.1 为什么必须自检

| 事实 | 后果 |
| --- | --- |
| `tools\*.ps1` 必须是 **UTF-8 带 BOM**（`PROJECT_RULES` 第七章；`tests\files-check.js` 第 115 行断言） | 丢 BOM 会把门禁打红 |
| PS 5.1 对**无 BOM** 的 `.ps1` 按系统 ANSI（本机 CP936）解析 | 脚本里的中文字面量（字体名「微软雅黑」等）被**静默**解码错，写进 docx ⇒ **全仓 docx 交付物**的东亚字体悄悄回退 |
| 更隐蔽的一种 | BOM 还在、正文却被"按 ANSI 读进来再存回去"损伤过 ⇒ 只看 BOM 的检查**查不出来** |

因此两个脚本**入口处**都带自检（`md2docx.ps1` / `md2docx-img.ps1` 顶部 `# ===== E15 入口 BOM 自检` 段）：

1. **第 1 条**：本脚本文件前 3 字节必须是 `EF BB BF`（BOM）；
2. **第 2 条**：本脚本文件里必须还能找到「微软雅黑」这 4 个汉字的 **UTF-8 字节**（`E5 BE AE | E8 BD AF | E9 9B 85 | E9 9B 85`）——用来发现"BOM 在、正文被 ANSI 往返重写"的损伤。

任一条不过 ⇒ 在 stderr 打印可读原因并 **退出码 3**，**不产出任何 docx**（宁可不出稿，也不出字体回退的稿）。

### 10.2 报错长什么样

```
  [FAIL] BOM SELF-CHECK FAILED - this script cannot produce a trustworthy .docx.
         reason   : missing UTF-8 BOM: first 3 bytes are not EF BB BF
         script   : D:\...\tools\md2docx.ps1
         howto    : rewrite the file as UTF-8 WITH BOM (EF BB BF), then re-run.
         ...
```

### 10.3 改完脚本怎么复查 BOM

**推荐命令**（只读，不改文件）：

```powershell
node -e "const b=require('fs').readFileSync('tools/md2docx.ps1');console.log(b.slice(0,3).toString('hex'), b.length)"
# 期望输出以 efbbbf 开头；若不是，用能保存 BOM 的编辑器重存为「UTF-8 with BOM」
```

或用仓库门禁一次看清全部 `tools\*.ps1`：

```powershell
node tests\files-check.js     # 第二节「BOM 用法（.ps1 必须带，其余必须不带）」
```

**纪律（踩过坑，务必遵守）**：

- 改 `tools\*.ps1`/说明文档**只用编辑工具或 Node 读写字节**；**禁止** `Get-Content -Raw | Set-Content -Encoding utf8`
  （PS 5.1 下是"按 ANSI 读 + 写 UTF-8 带 BOM"，**多字节字符被不可逆破坏**，且门禁的乱码特征常常查不出来）；
- 某些编辑器/工具保存时会**吃掉 BOM** ⇒ 每次改完都跑一次上面的复查命令；
- **断言失败信息不点名原因**时不要急着怀疑工具坏了 —— 先按本节两条判据自查。

## 十一、目标文件被占用时的行为（E14）

现场出交付物时常常开着 Word/WPS。脚本现在的行为：

| 时机 | 行为 |
| --- | --- |
| **转换前**（预检） | 以独占方式探测目标 `.docx`；被占用则打印可读提示并退出 **1**，**此时还没建构建目录、也没写任何临时件**（也不会有"半成品"） |
| 提示内容 | `[FAIL] 请先关闭 <文件名>（可能被 Word/WPS 打开）—— 目标文件当前被占用，本次转换已中止。` ＋ `target` / `cause` / `lock`（同目录 `~$*` 锁文件）/ `hint` |
| **失败时** | **先报告、再清理**：清掉本次的 `._docx_build`（含临时件）与同目录 `~$*` 锁文件。**E106 起不再删除任何目标文件** —— 旧件保持一个字节不变（见第十二节；旧版会删掉"本次新写出、但打包失败的半成品目标"） |
| **预检之后才被占用** | 落位（原子替换）失败 ⇒ 同一句可读提示 ＋ 退出 **1**；旧件仍然一个字节不变 |
| **正常路径** | 与改动前**逐字相同**（同样打印 `OK -> …`，退出码 0）；产物字节的对照读数见第十二节 |

要点：

- 「目标被占用」**不是**"转换工具损坏"——提示里会明说，并按"关掉文档后原样重跑"引导；
- 探测是**只读**的：不会改动被占用文件的一个字节；
- 若目标被**别的程序**（不是 Word/WPS）持有句柄，提示里会写「未见 `~$` 锁文件 —— 可能是别的程序/脚本持有句柄，或只读属性/权限不足」，避免误导；
- 关闭 Word/WPS 后，`~$*` 锁文件通常由 Office 自己删除；若残留，本脚本的清理会顺手删掉它（这也是 `tests\files-check.js`「无 `~$*` 临时文件」断言在意的形态）。

## 十二、安全写语义：失败也不许毁掉旧件（E106）

### 12.1 为什么必须"先写新件、再替换"，而不能"先删旧件、再写新件"

旧版打包函数的**第一句就是删掉已存在的目标 `.docx`**，第二句才开始写新包。于是"旧件已经没了"与"新件写成功"之间有一个**没有任何退路**的窗口：磁盘满、权限被拒、杀软/索引器/同步盘临时占住、写到一半 `Ctrl-C` 或进程被杀……任何一个落在窗口里，现场就从"**有一个旧版可交付**"变成"**一个都没有**"——这是**不可逆的内容损失**，不是格式问题。

现在改成：**先写临时件 ⇒ 自证完整 ⇒ 才做一次原子替换/改名**。旧件的命运被推迟到"新件已经完整躺在盘上"之后；原子替换要么完整成功、要么什么都没发生。⇒ 失败时旧件字节不变，靠的**不是**"失败后拿备份恢复"，而是"**失败时压根没有可恢复的动作发生过**"。

### 12.2 一次转换里各个物的去向

| 物 | 名字 / 位置 | 成功 | 失败（抛错 / 占用） | 真实 `Ctrl-C` | 进程被强杀 |
| --- | --- | --- | --- | --- | --- |
| 目标 `.docx` | 调用者给的 `-OutPath` | 被**完整新件**原子替换（目标原本不存在时同卷改名落位） | **一个字节都不动**（旧件保持原样） | **一个字节都不动** | **一个字节都不动** |
| 临时件 | `<输出目录>\._docx_build\_md2docx_pkg.new` | 被替换/改名消耗掉 | 随构建目录一起删 | 随构建目录一起删 | 可能残留（在构建目录内） |
| 备份件 | `<目标>.md2docx.bak`，只在"替换"那一瞬间存在 | 替换成功后立即删除 | 由失败清理删除（前提：目标仍在原位） | 不产生 | 不产生 |
| 构建目录 | `<输出目录>\._docx_build\` | 删除 | 删除 | 删除 | 可能残留 ⇒ **下一次运行入口自动清扫** |

要点：

- **临时件只放在构建目录内**（`._*` 前缀已被 `.gitignore` 与 `tests\files-check.js` 的扫描排除）⇒ 不引入新的残留形态；
- **备份件**只在 `File::Replace` 的**一次系统调用**里出现，成功即删 ⇒ 成功路径不会多出第二个交付物；
- **退出码**：成功 `0`；占用/写失败 `1`；**入口 BOM 自检不过 `3`**。⚠ 工具自身的 `3` 与测试门禁"整脚本跳过"的 `3` **不是一回事**，不要混读（`E107` 的裁定）；
- **实测读数**：`tests\._verify\T-20261005-02\`（`e106-probe.js` 四类失败注入 ＋ Ctrl-C ＋ 强杀；`e106-parity.js` 成功路径字节对照；`e106-encoding.js` 编码自证）。

### 12.3 调用者须知

1. **什么时候会改到旧件**：只有"新件已经完整生成并通过完整性自检"之后的**一次**原子替换/改名。在这之前，任何失败都不会碰到旧件（连打开写都没有）。
2. **同一目标不要并发转换**：构建目录名固定为 `._docx_build`，两个进程写同一个输出目录会互踩（与改动前一致）。
3. **`Ctrl-C` 是安全的**：实测 PowerShell 在 `Ctrl-C` 时会执行**词法上包住被打断语句的 `finally`**（`trap` 不会跑），因此构建目录与临时件会被清掉、旧件不动。
4. **强杀（任务管理器结束进程 / 断电）**可能留下 `._docx_build\`：它不含任何交付物、被 `.gitignore` 与门禁扫描排除，**下一次运行入口会先清掉它**，随后照常出稿。
5. **只读属性的旧件**：替换前会清掉它的只读位（与旧版 `Remove-Item -Force` 吃得下只读件的行为等价）。
6. **重新生成不保证与更早的旧件逐字节相同**：`word/*.xml` 等部件的**行尾跟随工具源文件**（现为 LF）。若旧件是更早（源文件为 CRLF）的版本生成的，两者字面不同而**内容等价**——这与本节修法无关，出稿对照读数已如实登记在 `T-20261005-02` 的取证里。
